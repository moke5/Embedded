# 内核

> Linux 内核是操作系统的核心，向上通过系统调用为进程提供服务，向下管理 CPU、内存与外设。

## 边界

| 层次 | 职责 | 仓库对应笔记 |
| --- | --- | --- |
| 用户空间 | 应用与库通过系统调用请求服务 | [Ubuntu](../Ubuntu.md)、[虚拟机](../虚拟机.md) |
| 系统调用接口 | 进程进入内核的入口 | [系统IO](../../文件IO/系统IO.md) |
| 内核 | 进程调度、内存管理、文件系统、设备驱动、网络协议栈 | 本文 |

内核不向应用直接暴露硬件寄存器；应用访问外设需要设备驱动或系统调用。中断与异常从硬件侧进入内核，系统调用从软件侧进入内核。

## 主要子系统

- 进程管理：进程与线程的创建、调度和销毁；调度策略决定 CPU 时间分配。见 [进程基本API](../../并发编程/进程基本API.md)。
- 内存管理：虚拟地址到物理地址的映射、页表与缺页处理。用户态 `malloc` 获得的地址在首次访问时由内核建立映射。
- 虚拟文件系统：用统一的文件接口访问文件、目录、设备与管道。见 [文件属性与目录操作](../../文件IO/文件属性与目录操作.md)。
- 设备驱动：把外设寄存器操作封装成内核接口。分层思路见 [STM32驱动分层设计](../../../杂记/技术专题/STM32驱动分层设计.md)。
- 网络协议栈：TCP/IP 协议处理位于内核，用户态通过套接字访问。见 [TCP编程基础](../../网络编程/TCP编程基础.md)。

## 学习路径

1. 在 [Ubuntu](../Ubuntu.md) 和 [虚拟机](../虚拟机.md) 中熟悉用户空间命令与目录结构。
2. 通过 [系统IO](../../文件IO/系统IO.md) 观察系统调用边界：`open/read/write` 如何进入内核。
3. 用 [进程基本API](../../并发编程/进程基本API.md) 理解进程与线程的创建。
4. 再看驱动分层，把用户态接口与硬件操作对应起来。
