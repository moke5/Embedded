## **基础概念**

### **1. 课程概览**

网络通信实际上就是广义的 IPC，但带IP地址的 IPC 要比单机 IPC 复杂很多，学习网络编程首先要理解网络分层的基本思想，进而引出网络协议的概念，网络编程很大程度上就是基于某种协议，编写符合协议规范的通信代码。

#### **1.1 网络分层**

由于网络数据的传输过程比较复杂，因此需要将传输过程按照所完成的功能进行分层，每一层对应一个单一的明确的功能，这样一来就使得每一层的实现方式容易形成行业标准，代码也易于维护。

![img](./img/wKgP3GITN1aAD-X3AAS_-5fK_Vg709.png)
<center>
    OSI（Open System Interconnection)七层理论模型
</center>



**TCP/IP 四层模型**
上述OSI的七层网络模型是一种理性模型，对应现实中实际存在的TCP/IP四层协议栈：

![img](http://edu.yueqian.com.cn/group1/M00/12/72/wKgP3GITN1aAVNDKAAJIeldGIDs278.png?token=null&ts=null)
<center>
    OSI理论模型与TCP/IP四层协议栈型
</center>



TCP/IP 四层模型是现行普适的网络层次模型。由顶层到底层是：

- 应用层：
    - 包含 OSI 模型中的最顶部三层，加密、压缩、编码、会话、语义等等功能统统是应用程序 APP 所辖范畴。
    - 应用程序 APP 可以很简单，也可以很复杂。
- 传输层（位于操作系统内核）：
    - 与 OSI 模型对应，负责传输控制。
- 网络层（位于操作系统内核）：
    - 与 OSI 模型对应，负责路由选择。
- 网络接口与物理层（位于操作系统内核）：
    - 这包括实际数据传输的物理媒介，及其对应的驱动层软件。

#### **1.2 网络协议**

协议就是通信双方预先商量好的一组“暗号”，将彼此之间需要协定的东西写入数据包的固定位置，大家使用相同的方式来解读这一组特定的信息，最终达到能互相理解对方意图的方式。

对应于不同的网络分层，每一层都有一个或多个协议，比如应用层中的 **HTTP、FTP、NFS、TELNET** 等等。在不同的网络拓扑和场景下，使用到的网络协议纷繁复杂，林林总总，但在互联网领域中，应用最为广泛的是所谓 TCP/IP 协议栈。

![img](./img/wKgP3GITN1aAfVLCAAEkYLkx7Pg829.png)
<center>
    互联网通用协议栈
</center>



TCP/IP 协议栈名称的由来是历史原因，它们并不仅指 TCP 协议和 IP 协议，广义上而言，协议栈囊括众多使用基于 IP 协议的应用层协议，传输层最重要的 TCP 和 UDP 协议，以及众多 IP 协议的辅助协议。

|       层次       | 协议                                                  |
| :--------------: | ----------------------------------------------------- |
|      应用层      | DNS, FTP, HTTP, IMAP, POP3, SMTP, SSH, Telnet, SSL, … |
|      传输层      | TCP, UDP, …                                           |
|      网络层      | IP (IPv4, IPv6), ICMP, ARP, …                         |
| 数据链路与物理层 | 802.3(Ethernet), 802.11(Wi-Fi), PPP, …                |

数据包在网络中传输时，发送方逐层对数据包进行对应协议的封装，这个过程类似于寄包裹的时候往包裹上贴标签。而接收方执行相反的过程，接收方拆包裹并读取对应协议信息（一般称为协议头）。如下图所示：

<center>
    各种协议的头部数据

### **2. 基本术语**

#### **2.2 IP地址**

IP 地址实质上等同于一台计算机的 ID，用来便于在世界范围内更加方便地唯一标识某一台机器。以 IPv4 为例，IP 地址总共32位，通常的形式是所谓点分式的字符串：

!![img](./img/wKgP3GITN1aAa1lNAAA7iFwceXQ455.png)
<center>
    IPv4地址
</center>



当初 IP 地址被发明出来的时候，人们觉得32位地址长度是足以表达世界上所有的计算机的，后来我们知道，随着信息科学的发展，目前世界上的计算机的数量（包括所有需要联网的设备，不仅仅是电脑）早已远远超过当初人们的设想，因此理论上32位的 IPv4 地址早已不够用，但人们后续发明了子网技术来有效地缓解了 IP 地址枯竭的问题，因此就目前而言 IPv4 还将长期存在。

一个 IP 地址从形式上可以分成前后两段，前半段称为网络号，后半段称为主机号。网络号用来作为该主机所在的网络在全世界范围内的唯一标识，主机号用来作为该主机在其所在的网络内部的唯一标识。由此，根据网络号和主机号所占位数的不同，将 IP 地址分为以下类别：

- A类地址
    - 第1字节为网络地址，其他3个字节为主机地址。
    - 第1字节的最高位固定为0
    - `1.0.0.1 – 126.255.255.255`
- B类地址
    - 第1字节和第2字节是网络地址，其他2个字节是主机地址。
    - 第1字节的前两位固定为10
    - `128.0.0.1 – 191.255.255.255`
- C类地址
    - 前3个字节是网络地址，最后1个字节是主机地址。
    - 第1字节的前3位固定为110
    - `192.0.0.1 – 223.255.255.255`
- D类地址（组播地址）
    - 不分网络地址和主机地址，第1字节的前4位固定为1110
    - `224.0.0.1 – 239.255.255.255`

**注意：**

1. 我们通常的主机IP是局域网地址，由局域网路由分配。
2. D类地址不是 IP 地址，而只是 UDP 协议的多播标识。

#### **2.3 子网属性**

在给windows主机配置网络时，常常会看到如下界面：

![img](./img/wKgP3GITN1aAAt4dAABOmS4GPXY298.png)
<center>
    IP地址、子网掩码和网关
</center>



IP地址与子网掩码相与之后的结果被称为网段：

```
网段 = IP & 子网掩码
```



上述例子中，子网掩码是 `255.255.255.0`，因此网段就是 `192.168.9.x`，局域网内通信的主机应该都要处于同一网段内，否则数据无法被该网段所属的网关（`192.168.9.1`）路由转发。

在很多场合下，子网掩码会以比特位的形式跟IP地址写在一起，例如上述子网属性可以写成：

```
192.168.9.88/24
```



后面的 `/24` 代表该IP地址所在的网段是前24比特位，也就是说子网掩码是 `255.255.255.0`

#### **2.4 端口号**

IP 地址可以唯一标识一台计算机，但通信的双方并不是两台计算机，而是计算机内部的进程。很明显，为了区分一台主机接收到的数据包应该转交给哪个进程来进行处理，使用端口号来加以区分。

端口号是一个短整型数据，长度为16位。具体分布：

- 系统端口：1~1023
- 注册端口：1024~49150
- 动态或私有端口：49151~65535（这是平常做实验可用的端口号范围）

**注意：**

- TCP端口号与UDP端口号独立
- 端口号一般由IANA (Internet Assigned Numbers Authority) 管理

[点击查看**TCP/UDP**常见端口](https://tool.oschina.net/commons?type=7)

##### **2.5 字节序**

当一个数据需要使用2个或以上字节来存储时，就会出现所谓字节序的概念。例如一个四字节数据，既可以将低有效位（78）放在低地址处，反之亦可放在高地址处。

```
int a = 0x12345678;
```

![img](./img/wKgP3GITN1aAB2IQAADbURuXaak509.png)
<center>
    字节序
</center>



通常，将最低有效位（即78）放在低地址的存储方式称为**小端序**，反之即**大端序**。在单机编程中，字节序是系统内部的存储细节，与程序无关。但在网络编程中，由于数据是在两台不同的机器中传输和表达，因此如果字节序不一致，则会出现牛头不对马嘴的现象。

解决这一困境的办法是，将网络中的数据，统一为某种固定的字节序，比如大端序。这样一来，凡是从主机往外发的数据，一律转换为大端序，凡是从网络接收的数据，也一律是大端序，网络字节序屏蔽了通信双方的具体细节，从而使得双方通信成为可能。

![img](./img/wKgP3GITN1aAQCAhAABlEd_5rTI898.png)

### **2. Ubuntu网络配置**

给虚拟机 VMware 选择了某一种联网模式后，一般还需要给客户机（即Ubuntu主机）配置好如下网络参数才能正常联网：

- 网卡名称
- IP地址
- 子网掩码
- 网关地址

#### **2.1 经典Linux网络配置**

在 `Ubuntu-17.10` 及以前的版本中，Ubuntu的网络配置围绕文件 `/etc/network/interfaces`（Ubuntu-17.10以后的新版本的网络设置请参考[本课件netplan配置](http://edu.yueqian.com.cn/learncenters.html?courseId=2080247109116563458#3)），可设置计算机的IP地址、子网掩码、默认网关，也可以选择固定IP和动态IP两种模式：

1. 设置固定IP：

```
gec@ubuntu:~$ cat /etc/network/interfaces
  # interfaces(5) file used by ifup(8) and ifdown(8)
  auto lo
  iface lo inet loopback

  auto ens33
  iface ens33 inet static
  address 169.254.54.200 # IP地址，根据具体的网络环境来写
  netmask 255.255.0.0    # 子网掩码
  gateway 169.254.54.1   # 网关地址
gec@ubuntu:~$
gec@ubuntu:~$
```



1. 设置动态IP（自动获取IP）

```
gec@ubuntu:~$ cat /etc/network/interfaces
  # interfaces(5) file used by ifup(8) and ifdown(8)
  auto lo
  iface lo inet loopback

  auto ens33
  iface ens33 inet dhcp
gec@ubuntu:~$
gec@ubuntu:~$
```



**注意1**
一般而言，只有在虚拟机设定为桥接模式下，才需要配置Ubuntu的网络参数信息，如果虚拟机设定的是NAT模式，那么一般直接重启网络服务，让其自动获取网络参数即可。

**注意2**
以上示例以虚拟网卡 `ens33` 为例，具体名称要以实际的为准，不能照抄，可以用命令 `ifconfig` 查看Ubuntu中已启动的网卡名称：

![img](./img/wKgP3GITN3WAHbgnAAEPehDoDdk186.png)
<center>
    ifconfig命令查看当前活跃的网卡名称
</center>



**重启网络服务**

```
# Ubuntu-14.04以前的版本：
gec@ubuntu:~$ sudo /etc/init.d/networking force-reload
gec@ubuntu:~$ sudo /etc/init.d/networking restart

# Ubuntu-14.04以后的版本：
gec@ubuntu:~$ sudo service networking force-reload
gec@ubuntu:~$ sudo service networking restart
```



**注意**
在更新的Ubuntu-17.10以后的版本中，网络配置用的是 [netplan](http://edu.yueqian.com.cn/learncenters.html?courseId=2080247109116563458#) 命令，而不是上述命令。

**测试网络**
有两个命令可以测试网络是否连通:

一、执行 `host` 通过DNS单次查询指定域名的IP和其他网络信息：

```
gec@ubuntu:~$ host www.qq.com
www.qq.com is an alias for ins-r23tsuuf.ias.tencent-cloud.net.
ins-r23tsuuf.ias.tencent-cloud.net has address 121.14.77.201
ins-r23tsuuf.ias.tencent-cloud.net has address 121.14.77.221
ins-r23tsuuf.ias.tencent-cloud.net has IPv6 address 2402:4e00:1020:1404:0:9227:71a3:83d2
ins-r23tsuuf.ias.tencent-cloud.net has IPv6 address 2402:4e00:1020:1404:0:9227:71ab:2b74
```



二、执行 `ping` 命令，测试网络是否连通。注意当有返回延时时间时，就代表网络是通的；如果卡主不动，代表网络不通或者网络拥塞：

```
gec@ubuntu:~$ ping www.qq.com # 测试互联网上某域名服务器是否网络可达
gec@ubuntu:~$ ping 192.168.1.100 # 测试局域网内某主机（比如开发板）是否网络可达
```

## 常用网络调试工具

### **1. 网络命令**

在网络编程的时候，经常需要借助于一些命令来查看某个网卡或某个连接的信息，动态地调测网络数据的收发细节。

#### **1.1 netstat**

netstat 命令用于显示各种网络相关信息，如网络连接，路由表，接口状态 (Interface Statistics)，masquerade 连接，多播成员 (Multicast Memberships) 等等。

**直接运行**
![img](./img/rBJlJmMOFKSAAAgrAACgQvzvyg0339.png) 

可见，netstat会显示两部分信息：

- 激活的Internet连接信息
    - 就是真正的网络连接，显示TCP和UDP当前激活的连接情况
- 活跃的Unix域套接字信息
    - 即所谓本地域套接字，是一种高效但只能在本地通信的IPC

**常用的基本参数**

```
-t : 查看TCP协议相关信息（默认只看到处于ESTABLISHED状态的信息）
-u : 查看UDP协议相关信息（默认只看到处于ESTABLISHED状态的信息）
-a : 显示所有信息，包括不处于ESTABLISHED状态的信息
-n : 使用数字显示，而不是别名
-l : 只看处于LISTEN状态的信息
-s : 按协议输出统计信息
-i : 显示活跃网口的信息
-r : 显示路由信息
-c : 持续跟踪输出
-p : 显示与连接相关的进程信息
```



一般而言，上述参数都不是单独使用的，都是配套使用，并且为了更好地达到目的，一般会将 `netstat` 跟别的命令一起联合使用。

**组合命令举例**

```
# 列出所有处于ESTABLISHED状态的TCP/UDP信息
netstat -tu

# 找到使用某端口（比如50001）的连接
netstat -an | grep ':50001'

# 列出所有处于监听状态的套接字
netstat -an | grep 'LISTEN'
```



#### **1.2 netcat(nc)**

netcat，在网络工具中有**瑞士军刀**美誉，其有Windows和Linux的版本。因为它短小精悍（1.84版本也不过25k，旧版本或缩减版甚至更小）、功能实用，被设计为一个简单、可靠的网络工具，可通过 `TCP` 或 `UDP` 协议传输数据。同时，它还是一个网络应用Debug分析器，因为它可以根据需要创建各种不同类型的网络连接。

netcat有许多功能，它可以在两台设备上面相互交互，即侦听模式/传输模式，它甚至包括这些功能：

- Telnet功能
- 获取banner信息
- 传输文本信息
- 传输文件/目录
- 加密传输文件，默认不加密
- 远程控制

在 `Linux` 下，可以通过 `nc -h` 获取帮助：

![img](./img/rBJlJmMOFKSADcGQAAHTqduSe2U947.png)

- 启动一个指定端口的TCP服务器

#### **2.2 基本使用步骤**

初次使用 `wireshark` 都会感觉其功能强大，界面复杂，学习门槛高，但如果仅限于使用其来抓取对应网卡数据包，用于学习、验证各种不同网络协议通过真实物理设备时的数据封装形式，则其应用并不困难。总体而言，只需掌握如下几点便可：

1. 选择正确的监控网络接口
2. 编写正确的捕获、显示过滤器
3. 认识如何查看数据包，尤其是通信协议的内容

下面来一个个说。

**一）网络接口的选取**
在wireshark的起始界面，首先要选择需要监控的网卡：

![img](./img/rBJlJmMOFKSAQVQYAAB8ZLoZ6Eo141.png)
<center>
    选择要监控的网卡
</center>



假设在A同学的虚拟机ubuntu-1中运行一个网络通信测试用例，在另一位B同学的虚拟机ubuntu-2中运行对端网络通信测试用例，那么它们之间的网络数据必然会通过物理机中的真实网卡，那么只需在windows版本的wireshark中监控某个网卡即可。具体而言：

- 如果虚拟机是桥接模式，那么就监控虚拟机所桥接的网卡
- 如果虚拟机是NAT模式，那么就监控VMnet8

如果是某同学自己的同一台虚拟机ubuntu中，启动了两个网络通信测试用例，那么这些网络数据将不会通过任何物理真实网卡，甚至也不会通过任何虚拟网卡，而仅仅通过虚拟机ubuntu中的本地回环设备 `lo` 进行传递，因此这种情况下如果想要抓包分析，那么一般需要安装ubuntu本班的wireshark，并且使之监控ubuntu中的 `lo` 网卡。

更加详细的信息请参阅上一篇课件《教案02-虚拟机网络配置》。

如下图所示，在指定某个监控网卡之后，如果该网卡处于活跃状态，一般会发现从网卡通过的数据包会非常多，使得目标数据包难以被发现，因此一般需要编写 **过滤器表达式** 来捕获符合条件的数据包。

wireshark支持两种过滤器，一是**捕获过滤器**，一是**显示过滤器**，顾名思义，捕获过滤器在过滤之前就做出筛选，直接无视不符合要求的数据包，这样能节约大量磁盘空间资源，而显示过滤器则是在捕获了的数据包的基础上，再对显示列表做进一步筛选，这两种过滤器的位置如下图所示：

![img](./img/rBJlJmMOFKSAFLQlAAB8csqV340622.png)
<center>

</center>



**示例1**
设置捕获过滤器，使之只捕获TCP协议且端口号包含50001（即源端端口或目的端端口）的数据包：

```
tcp port 50001
```



![img](./img/rBJlJmMOFKSALaHKAAE4OTDyxK4002.png)
<center>
    设置捕获过滤器
</center>



**示例2**
设置显示过滤器，使之只显示TCP协议且端口号包含50001（即远端端口或目的端端口）的数据包：

```

```



![img](./img/rBJlJmMOFKSAYd8GAABJXZ2xrX4316.png)
<center>
    wireshark显示过滤器
</center>



一条基本的过滤器表达式由过滤项、过滤关系和过滤值构成，比如 `ip.addr == 192.168.1.100` 这个表达式中：

- `ip.addr` 是过滤项
- `==` 是过滤关系
- `192.168.1.100` 是过滤值

整个表达式的意思是：找出所有IP协议中源主机或目标主机的IP地址等于`192.168.1.100`的数据包。

**过滤项**
过滤项一般的构成是由 **`协议.协议字段`** 构成。

- 协议
    - eth
    - ip
    - tcp
    - udp
    - snmp
    - icmp
    - ftp
    - http
    - telnet
    - oicq
- 字段（该协议下的关键属性）
    - addr
    - port
    - dstport
    - payload
    - ack

因此他们的组合可以是：
`tcp.port == 50001`
`udp.dstport >= 1024`
`oicq.qqid == 2437231462`

**过滤关系**
过滤关系就是大于、小于、等于这些逻辑关系，在显示过滤器中有两种写法，一种是英文模式，一种是代码模式，比如过滤端口为50001的写法可以是以下两种写法之一：
`tcp.port == 50001`
`tcp.port eq 50001`

具体的写法可以参考官方给定的下表：

| 英文模式    | 代码模式 | 说明                             | 举例                                       |
| ----------- | -------- | :------------------------------- | ------------------------------------------ |
| eq          | ==       | 相等                             | `ip.src == 10.0.0.5`                       |
| ne          | !=       | 不相等                           | `ip.src != 10.0.0.5`                       |
| gt          | >        | 大于                             | `frame.len > 10`                           |
| lt          | <        | 小于                             | `frame.len < 128`                          |
| ge          | >=       | 大于或等于                       | `frame.len ge 0x100`                       |
| le          | <=       | 小于或等于                       | `frame.len <= 0x20`                        |
| contains    |          | 协议、字段或片段包含某个指定的值 | `sip.To contains "a1762"`                  |
| matches     | ~        | 协议或文本字段匹配正则表达式     | `http.host matches "acme\\.(org|com|net)"` |
| bitwise_and | &        | 位与操作                         | `tcp.flags & 0x02`                         |

**过滤值**
过滤值就是设定的过滤项应该满足的标准，一些具体的数值。

wireshark其他更深入的教程，有兴趣的话可以参考官方手册：[wireshark 用户手册（英文）](https://www.wireshark.org/docs/wsug_html/#DispCompOps)

## QA

【1】问：使用wireshark抓取ubuntu系统的网络数据包时，应该选哪个网卡？
【1】答：先试用命令 `ifconfig` 查看当前活跃的网络接口：

![img](./img/rBJlJmOIRN6APzqrAACTqbkAa8s857.png)

遵循的原则是：

- 如果是虚拟机内部多个进程之间的网络通信，则要抓取本地回环设备 `lo` 的数据，因为本机内的网络数据都不会真正经过网卡，都只在lo之间内部转发
- 如果是多台物理主机之间的网络通信，那么抓取任意一台物理机的网卡或虚拟机的虚拟网卡均可。

【2】问：为什么有时可以给云主机发送数据，但是却收不到云主机的数据？
【2】答：由于安全和资源管理的具体原因，子网内的主机跟互联网一般是隔离的，也就是说被路由器所辖的子网对外是透明的，互联网看到的只能是路由节点，看不到子网内部各个主机的信息。

![img](./img/rBJlJmOIRN6AKKlTAABV0oMEcQs648.png)

我们可以给云主机发送数据，是因为云主机服务器对发往公网的数据做了内网转发，是他帮我们做了TCP/UDP透传或端口映射；而反过来从服务器发来的数据到达了家里或公司的路由器，如果我们没有做网络透传或端口映射，那么数据包将会被路由器丢弃。

要实现家里或公司的内网电脑接收服务器发来的数据包，最简单的方式就是在路由器设置端口映射，以笔者所在的局域网为例，实验电脑的地址是 `192.168.0.148:50021`，因此在本地路由将此端口做好映射之后，外网主机向笔者所在的子网发送的数据才会被路由器透传到主机 `192.168.0.148:50021` 中去：

![img](./img/rBJlJmOIRN6AWqn7AAEDOYEqPmw558.png)
<center>
    端口映射
</center>
