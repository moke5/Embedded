I/O 多路复用

用一个线程监控成千上万个连接 —— 从 select 到 epoll，理解现代高并发服务器的基石。

💡 本教程含 交互式演示，请动手点击、观察，效果更佳。

1什么是 I/O 多路复用？

I/O 多路复用（I/O Multiplexing）是一种让单个线程同时监控多个文件描述符的技术。 当其中任意一个（或多个）描述符就绪（可读/可写/异常）时，程序就能得到通知并处理。

🏢 一个生活比喻

假设你是一家餐厅的服务员：

  • 阻塞 I/O：你站在 1 号桌前，等客人点完菜、吃完、结账，才去 2 号桌 —— 一桌一桌服务，效率极低。
  • 多线程：每桌配一个服务员 —— 人多了，成本爆炸（线程切换开销大）。
  • I/O 多路复用：你一个人来回巡视所有桌子，谁举手（就绪）就去谁那里 —— 高效、省资源。

核心思想

监控

一次性告诉内核：我要关注这些 fd 的事件。

等待

阻塞在系统调用上，直到某个 fd 就绪。

处理

被唤醒后，只处理那些"举手"的 fd。

2阻塞 I/O 的困境

先看看没有多路复用时，一个服务器会怎么写：

// 传统阻塞服务器：一次只能处理一个客户端
while (1) {
    int conn = accept(listen_fd, ...);  // 阻塞等连接
    read(conn, buf, ...);            // 阻塞等数据
    process(buf);
    write(conn, ...);               // 阻塞等发送
    close(conn);
}

这段代码的问题：当它正在服务客户端 A 时，完全无法响应客户端 B 的连接请求。

😱 问题总结

  • 无法并发：一个慢客户端会拖死所有人。
  • 浪费资源：CPU 大部分时间在"等待"，什么都没干。
  • 多线程也救不了：线程数有限，上下文切换开销随连接数增长。

3select —— 多路复用的起点

POSIX 标准最早提供的多路复用接口，通过位图管理 fd 集合。

fd_set read_fds;
FD_ZERO(&read_fds);
FD_SET(fd1, &read_fds);
FD_SET(fd2, &read_fds);

int n = select(maxfd + 1, &read_fds, NULL, NULL, NULL);
for (int i = 0; i <= maxfd; i++) {
    if (FD_ISSET(i, &read_fds)) {
        // fd i 就绪，处理它
    }
}

select 的三个致命缺陷

缺陷 1

fd 数量受限

fd_set 用位图实现，默认最多 1024 个 fd（FD_SETSIZE）。

缺陷 2

O(n) 轮询

内核每次都要遍历所有 fd 检查是否就绪，fd 越多越慢。

缺陷 3

重复拷贝

每次调用都要把整个 fd_set 从用户态拷到内核态。

4poll —— 换用数组，突破 1024

poll 用结构体数组替代位图，没有数量上限，但本质仍是O(n) 轮询。

struct pollfd fds[N];
fds[0].fd = fd1;  fds[0].events = POLLIN;
fds[1].fd = fd2;  fds[1].events = POLLIN;

int n = poll(fds, N, -1);
for (int i = 0; i < N; i++) {
    if (fds[i].revents & POLLIN) { /* 处理 */ }
}
对比项selectpoll
数据结构位图 (fd_set)结构体数组
最大 fd 数1024 (可编译改)无上限
事件类型读/写/异常更丰富 (POLLIN/OUT/ERR/HUP...)
时间复杂度O(n)O(n)
重复拷贝每次全量每次全量

关键结论：poll 只是解决了 fd 数量限制，O(n) 扫描和重复拷贝两个性能瓶颈依然存在。真正的飞跃要等 epoll。

5epoll —— 现代 Linux 的答案

epoll 通过三个系统调用彻底重构了多路复用：

创建

epoll_create

在内核创建一个 epoll 实例（红黑树 + 就绪链表）。

管理

epoll_ctl

增/删/改监控的 fd，只拷贝一个 fd 到内核。

等待

epoll_wait

直接返回就绪链表中的事件，复杂度 O(1)。

epoll 的两大核心数据结构

全量管理

🌲 红黑树

存储所有被监控的 fd。增删改查都是 O(log n)，用于 epoll_ctl。

快速就绪

📋 就绪链表

只存已就绪的 fd。网卡收到数据 → 软中断 → 回调 → 链入此链表。用于 epoll_wait。

为什么 epoll 快？

  1. 无重复拷贝：fd 只在 epoll_ctl 时拷贝一次，之后一直留在内核红黑树里。
  2. 无轮询：内核用回调机制，数据到达时主动把 fd 加入就绪链表，不需要扫描所有 fd。
  3. 返回即结果：epoll_wait 直接返回就绪列表，用户无需遍历全部 fd。

🌲 红黑树（所有被监控的 fd）
📋 就绪链表（epoll_wait 直接取）
// epoll 典型使用流程
int epfd = epoll_create1(0);
struct epoll_event ev, events[64];
ev.events = EPOLLIN;
ev.data.fd = listen_fd;
epoll_ctl(epfd, EPOLL_CTL_ADD, listen_fd, &ev);

while (1) {
    int n = epoll_wait(epfd, events, 64, -1);
    for (int i = 0; i < n; i++) {
        // 只处理就绪的，不需要扫描全部
    }
}

6LT vs ET —— epoll 的两种触发模式

这是 epoll 最容易踩坑的地方，也是面试高频考点。

默认

水平触发 LT

只要缓冲区有数据，就一直通知。

  • ✅ 编程简单，不用一次读完
  • ✅ 支持阻塞 socket
  • ⚠️ 可能重复通知，开销略大
EPOLLET

边缘触发 ET

只有状态变化时才通知一次。

  • ✅ 通知次数少，性能更高
  • ⚠️ 必须一次读完（读到 EAGAIN）
  • ⚠️ 必须非阻塞 socket

ET 模式的正确姿势

// ET 模式必须：非阻塞 + 循环读到 EAGAIN
set_nonblock(conn_fd);

while (1) {
    int n = read(conn_fd, buf, sizeof(buf));
    if (n > 0) {
        process(buf, n);
    } else if (n == 0) {
        // 对端关闭
        break;
    } else {
        if (errno == EAGAIN || errno == EWOULDBLOCK)
            break;  // 读干净了，退出
        else
            /* 真错误 */;
    }
}

🎯 选型建议

  • 连接数少（< 1024）：select / poll 足够，跨平台。
  • 连接数多、Linux 环境：无脑选 epoll。
  • 需要跨平台：Linux 用 epoll，macOS/BSD 用 kqueue，Windows 用 IOCP —— 可封装统一接口（如 libevent、libuv）。
