## **一、什么是 TRAE IDE**

TRAE IDE 是一款由 AI 驱动的集成开发环境，它不只是一个代码编辑器，更像是一名能够理解需求、调用工具并独立完成各类开发任务的“AI 开发工程师”。它内置了先进的大语言模型，能够深度参与编码、调试、重构、测试甚至部署环节，帮助你高效推进每一个项目。

TRAE 的核心理念是：**让 AI 从“辅助者”变为“执行者”**。你只需要描述目标，AI 就可以自动规划步骤、生成代码、运行测试，甚至主动修复错误。这种全新的人机协作模式，将大幅降低开发门槛，同时提升专业开发者的产出效率。

**1.1 满足个人与企业需求**

TRAE IDE 提供个人版与企业版两种形态，面向不同用户规模与使用场景，满足从个人开发到企业级协作的多样化需求。

**个人版**

提供完整的 IDE 核心能力，支持多种主流编程语言（如 Python、JavaScript、TypeScript、Java、Go 等）与热门开发框架。集成代码编辑、智能补全、调试运行、版本控制（Git）等一体化工具链。适合独立开发者、学生及自由职业者，用于项目开发、技术学习与实践探索。个人版免费使用，注册即可激活全部 AI 功能。

**企业版**

在个人版完整 IDE 能力的基础上，进一步增强团队协作与管理能力。主要特性包括：

- 成员与权限管理：支持按项目或团队分配角色，控制代码访问与操作权限。

- 资源用量监控：可视化查看团队对 AI 模型的调用次数、Token 消耗等。

- 企业级数据看板：展示项目进度、代码质量、AI 应用效率等关键指标。

- 内部 AI 模型接入：支持对接企业私有化部署的大模型，满足数据不出境、不出企的安全要求。

- 合规与审计：记录关键操作日志，满足 ISO、SOC2 等合规标准。

企业版适合中型及以上研发团队，尤其是对数据安全与开发流程规范有严格要求的行业，如金融、医疗、政务等。

**1.2 覆盖全开发流程**

TRAE IDE 不只是一款编码工具，它覆盖了从需求理解到上线的完整生命周期：

- 编码：IntelliSense 级别的智能补全，支持上下文推理与跨文件关联。
- 调试：智能定位错误，AI 可解释异常并提供修复建议。
- 测试：自动生成单元测试、集成测试，甚至能模拟边缘情况。
- 重构：识别代码坏味，一键进行安全的重构操作。
- 部署：集成主流云平台（如 Vercel、CloudBase），AI 可帮你生成部署配置。

特别值得一提的是内置的智能体编程工具 **CUE**，它支持：

- 代码补全：多行、整函数甚至整类的实时补全。

- 多行修改：用自然语言描述修改意图，AI 同时修改多个位置。

- 智能导入：自动管理依赖导入，删除无用包。

- 智能重命名：语义级重命名，准确识别所有引用点。

这些能力让你从繁琐的重复操作中解放出来，更专注于创造性工作。

**1.3 内置 AI Coding 智能体：SOLO Coder**

TRAE IDE 在 SOLO 模式中配备专属 Coding Agent —— **SOLO Coder**。它是面向复杂项目开发的自主智能体，能够理解自然语言描述的任务，自动拆分步骤、编写代码、运行测试，直至产出可执行成果。

SOLO Coder 的典型工作流：

2. 接收你输入的任务描述（例如“帮我创建一个用户登录 API，包含 JWT 认证”）。

2. 自动规划实现路径，生成任务清单。

2. 逐项执行：创建文件、编写代码、安装依赖、运行测试。

2. 若出现错误，自动读取错误日志并尝试修复。

2. 最终交付可运行的项目，并附上使用说明。

在这个过程中，你可以全程介入，随时调整方向或接管控制。SOLO Coder 尤其适合功能迭代、原型验证、小型工具开发等场景，能 10 倍提升复杂任务的推进速度。

**1.4 提供双重模式**

TRAE IDE 提供两种互补的开发模式，通过界面左上角一键切换：

**IDE 模式**

保留传统开发流程，你仍然是唯一的控制者。AI 以辅助形态存在，提供补全、解释、重构建议，但不会自主修改文件。适合对代码掌控力要求严苛的场景，或者在学习、探索代码时使用。

**SOLO 模式**

以 AI 为主导的开发模式。你可以直接交付一个“需求文档”，SOLO Coder 会自主完成后续所有工作。适合快速出原型、自动修复 bug、批量生成样板代码等任务。两种模式的数据完全互通，你可以随时将 SOLO 产生的代码切回 IDE 模式继续手动优化。

**实战建议：先用 SOLO 模式快速生成项目骨架和核心功能，再切回 IDE 模式精调细节，这是目前效率最高的开发范式。**

**1.5 拥抱开放的智能体生态**

TRAE IDE 推出全新可自由配置的**智能体（Agent）体系**，打造一个开放的智能体生态。你可以根据需求独立创建智能体，并分享到市场，就像在插件商店分享扩展一样简单。

智能体可以封装特定的角色、知识、工具集合，实现场景化复用：

- 前端组件生成智能体：你只需描述 UI 需求，它直接输出 React/Vue 组件代码。

- 数据库助手智能体：连接数据库，帮你写 SQL、分析表结构、生成迁移脚本。

- 代码审阅智能体：按照团队规范审查代码，给出修改意见。

- 文档翻译智能体：将注释和文档自动中英互译。

这种高度可定制的生态，让每个人（或每个团队）都可以训练出最懂自己项目的 AI 伙伴。

## **二、安装 TRAE 并完成初始设置**

**2.1 下载与安装**

1. 访问官网

打开浏览器，进入 [TRAE 官网](https://www.trae.com.cn/)。网站会自动识别你的操作系统（Windows/macOS/Linux），提供对应的下载选项。

1. 下载安装包

点击页面右上角的 **“下载 IDE”** 按钮。如果按钮包含下拉菜单，请根据自己的操作系统选择正确版本。注意区分 Intel 芯片与 Apple Silicon 芯片的 Mac 版本。

2. 安装

- Windows：双击 .exe 文件，按向导完成安装，建议勾选“添加到 PATH”（方便命令行使用）。

- macOS：将 .dmg 中的 TRAE 拖入 Applications 文件夹。首次打开若提示“无法验证开发者”，需在系统设置-安全性与隐私中点击“仍要打开”。

- Linux：根据发行版选择 .deb 或 .rpm 包，或直接使用 AppImage。

**2.2 初始化向导**

首次启动 TRAE，会弹出设置向导，建议逐步完成，这将影响后续的使用体验。

**选择主题和语言**

提供深色/浅色及高对比度主题，可根据环境光线和个人偏好选择。界面语言支持简体中文、英文等，后期可在设置中更改。

**从 VS Code 或 Cursor 导入配置**

如果你之前使用 VS Code 或 Cursor，TRAE 可一键导入以下内容：

- 已安装的插件列表（并自动安装兼容插件）

- 快捷键映射（可选择保持原习惯）

- 设置项（如字体大小、Tab 大小、格式化规则等）

- 代码片段

导入过程会清晰列出每一项，你可以按需勾选。这是一个非常贴心的迁移功能，能让老用户几乎零成本切换。

**添加命令行工具**

向导会提示你将 trae 命令注册到终端。启用后，你可以在终端输入 trae . 快速打开当前目录为项目。如果跳过了该步骤，后续也可以通过 Ctrl+Shift+P 输入 Shell Command: Install 'trae' command in PATH 进行安装。

**登录账号**

TRAE 支持手机号和稀土掘金账号登录。登录后才能调用 AI 模型。个人版在登录后即激活全部 AI 能力，企业版用户需联系管理员获取企业账号。

![img](./img/56699.png)

**2.3 打开项目**

初始化完成后，你可以直接导入一个本地文件夹或克隆一个 Git 仓库来开始工作。

**方式一：本地文件夹**

在欢迎页点击“打开文件夹”，或通过菜单 文件 > 打开文件夹 选择项目目录。TRAE 会读取项目结构，并为识别的语言自动推荐安装相关插件。

**方式二：克隆 Git 仓库**

点击“克隆 Git 仓库”，输入远程仓库 URL 和本地保存路径，即可自动 git clone 并在 TRAE 中打开。你也可以使用 Ctrl+Shift+P 执行 Git: Clone 命令。

打开项目后，左侧的资源管理器会显示文件树，右侧是编辑区，底部是终端——格局与传统 IDE 非常相似，上手无压力。

**2.4 切换 IDE 模式与 SOLO 模式**

在 TRAE 界面左上角，你可以看到一个模式切换开关。点击即可在 **IDE 模式** 和 **SOLO 模式** 之间切换。

- IDE 模式：经典编辑器布局，AI 以侧边栏聊天窗口、内嵌提示等形式提供帮助。你完全掌控文件修改，AI 不会自动更改代码。

- SOLO 模式：界面中央会出现任务输入框，底部是任务执行流。你在对话框中输入需求，SOLO Coder 便开始执行。该模式会主动创建/修改文件、运行命令，你需要授予必要的权限。

建议初次使用时，先打开一个小型项目，两种模式都尝试一遍，感受二者的差异。之后便能根据任务类型灵活选择。详情可参阅 [SOLO 模式概览](https://docs.trae.cn/ide/solo-mode)。

 

## **三、基于TraeAI创建智能体**

Trae 的智能体体系允许你定义专属的 AI 助手，实现特定领域知识的固化与复用。创建过程完全可视化，无需编写配置文件。

**3.1 进入智能体管理页面**

在 TRAE 主界面左侧活动栏，点击“智能体”图标，即可打开智能体面板。

![img](./img/56700.png)

面板包含两部分：

- 我的智能体：你创建或收藏的智能体。

- 智能体市场：社区分享的公开智能体，可以直接安装使用。

**3.2 创建新智能体**

点击“创建智能体”按钮，进入配置界面。

 

![img](./img/56701.png)

需要填写以下几个关键信息：

**基本信息**

- 名称：为智能体起一个见名知意的名字，如“Python 代码审查员”。

- 描述：简要说明该智能体擅长处理什么任务，会显示在市场列表中，帮助别人理解用途。

- 图标：可上传自定义图片，或从内置图标库中选择。

**角色与指令（System Prompt）**

这是智能体的“灵魂”。在“系统提示词”框中，用清晰、具体的语言定义智能体的身份、能力边界和行为规范。例如：

你是一名资深的微信小程序开发专家，专精于物联网小程序通信开发。

提示词写得越具体，智能体的表现就越稳定。还可以在提示词中加入特定的知识引用，如“请参考项目中的 docs/编码规范.md”。

**模型选择**

为智能体选择一个底层模型。不同模型在速度、推理能力和成本上有差异。通常复杂任务选用高级模型，简单任务选用轻量模型以节省资源。

**工具与能力**

你可以为智能体授予特定工具权限，其可选工具与 IDE 内置能力对齐：

- 读取文件

- 搜索代码

- 运行终端命令

- 读写数据库（需配置连接）

- 访问网络 API 等

合理配置工具可以避免智能体“越权”，保障安全。

## 二、连接巴法云失败的修复（关键提示词）
 
```
当前小程序连接巴法云失败，请对照官方文档 https://cloud.bemfa.com/docs/src/mqtt.html 排查并修复。
 
【已发现的问题】
1. wx.connectSocket 传了 header: {'content-type': 'application/json'}
   → WebSocket 握手不需要 HTTP content-type，会干扰服务器，必须删除
2. wx.connectSocket 传了 protocols: ['mqtt']
   → 巴法云文档未要求子协议，强行传会握手失败，必须删除
3. SocketTask.send 传了 isBuffer: true
   → 不是有效参数，删除
4. 心跳间隔 60s 与 CONNECT 报文 Keep Alive 60s 临界值相同
   → 改为 30s，留缓冲
5. 增加详细日志：onClose 打印 code/reason/wasClean，onMessage 打印 hex 前缀
 
【真机必做提醒】
必须在微信公众平台-开发设置-服务器域名中添加 wss://bemfa.com 到 socket 合法域名。
开发者工具调试时勾选「不校验合法域名」可临时测试。

## 三、状态显示错误修复（关键提示词）
 
```
问题：传感器收到数据但状态显示「订阅者/发布者离线」
 
【根因】
- 巴法云温湿度消息格式 #28.0#57.6 以 # 开头
- 之前代码把 # 开头当作「发布者状态消息」处理
- #28.0#57.6 被解析为 status=28.0#57.6，不等于 online → publisherStatus='离线'
 
【修复方案】
状态判断逻辑改为：
- $online / $offline → 订阅者状态消息
- #online / #offline → 发布者状态消息
- 其他 # 开头（如 #28.0#57.6）→ 普通数据消息，发布者在线+订阅者在线
- 其他 $ 开头 → 普通数据消息
- 任何非空数据消息 → 发布者在线、本机订阅者在线
- MQTT 连接成功时，所有已订阅设备的订阅者标记为在线
```

## 五、JSON BOM 错误修复提示词
 
```
真机调试报错：app.json SyntaxError: Unexpected token ﻿ in JSON at position 0
 
【根因】
﻿ 是 UTF-8 BOM 字符（\uFEFF），微信小程序运行时不接受 BOM。
 
【修复方案（Windows 环境）】
- 使用 Python 脚本读取二进制，去除前 3 字节 EF BB BF，写回
- 或使用 .NET API：UTF8Encoding(false) 写入无 BOM 字节流
- 避免使用 PowerShell 内联脚本（$ 变量转义问题）
- 修复后用 json.load 验证语法
- 用户操作：关闭开发者工具，清缓存，重新编译
```

## 六、关键工程注意事项（踩坑总结）
 
```
1. 巴法云 MQTT WebSocket 不能传 protocols 和 header
2. 文件保存必须 UTF-8 无 BOM（Windows 下编辑器默认会加 BOM）

4. 同理 $ 开头也要判断后续关键字
5. MQTT 消息可能是 ArrayBuffer（真机），不能假定是 string

**五、常见问题与技巧**

**Q：注册后 AI 功能无法使用？**

A：确认已登录账号，并检查网络连接。部分企业网络可能限制 AI 模型接口，需配置代理。

**Q：导入 VS Code 配置后插件未完全安装？**

A：部分不兼容的插件会被跳过，可到插件市场手动搜索替代品。TRAE 兼容大部分 VS Code 插件。

**Q：SOLO 模式生成的代码出错怎么办？**

A：将报错信息复制粘贴给 SOLO Coder，它会尝试读取文件并自动修复。也可以切回 IDE 模式手工修正，这是完全允许的混合工作流。

**Q：智能体市场中的智能体安全吗？**

A：安装前可以查看其配置和权限。智能体运行在沙盒中，无法在未授权情况下读取用户文件或执行网络请求，但仍建议优先使用官方或可信开发者发布的智能体。

**Q：企业版如何接入内部模型？**

A：联系 TRAE 官方技术支持，提供模型接口规范，即可完成对接。这个过程通常由平台运维和提供方共同完成。
