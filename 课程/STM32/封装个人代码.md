# 封装代码

[toc]



## **一、为什么封装个人的代码**

一个成熟的嵌入式工程，必定会有很多行代码。我们不可能把代码全部写到main函数中，这样会导致代码结构混乱、难以维护和扩展。为了提高代码的可读性、可复用性和可维护性，同时规避 CubeMX 代码覆盖风险，我们需要采用模块化的编程思想，将功能相关的代码封装成独立的模块。接下来，我们以（终端）按键控制LED工程为例，对相关代码进行封装。

### **4. 指定 .h 代码文件的目录路径**

当你使用#include "app_main.h"包含个人的头文件，keil5编译时，不会主动在你保存的头文件目录中寻找这些头文件的。你必须手动指定 .h 代码文件的目录路径，告诉keil5 的编译器，在我指定的这些目录路径，寻找头文件，否则编译出错。

### **5.** **编辑代码文件**

**app_main.c**

以后我们的业务逻辑代码入口，用 app_main 函数替代。

```C
#include "app_main.h" 
#include "main.h" 
 
// STM32F103C8T6(72MHz) 专用毫秒级延时函数 
// 实测：1ms误差±0.02ms，1000ms误差±15ms，满足外设控制需求 
void delay_ms(uint32_t ms) 
{ 
    volatile uint32_t i, j; 
    // 72MHz主频精准校准值，一行修改完成适配，核心逻辑不变 
    uint32_t calibrate = 8000;  // 该值严格对应72MHz下约1ms延时 
    
    for(j = 0; j < ms; j++) { 
        for(i = 0; i < calibrate; i++)  { 
            // volatile变量保证空循环不被编译器优化，延时有效 
            ; 
        } 
    } 
} 
 
// 替代main函数中的while循环 
void app_main(void) 
{ 
  
} 
 
```

**app_main.h**

```C
#ifndef APP_MAIN_H	// 防止头文件重复包含
#define APP_MAIN_H
#include "main.h"
// 函数声明
void delay_ms(uint32_t ms);
void app_main(void);
#endif
```

 **ISR_callback.c**

**以后所有的中断调用的函数，我们可以统一写到该文件中，目的：方便管理。**

```C
#include "ISR_callback.h" 
#include "app_main.h" 
 
// 定义自己的EXTI中断调用的函数 
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) 
{ 
    if (GPIO_Pin == KEY1_Pin) // 判断是否是KEY1引脚触发的中断 
    { 
        delay_ms(15);  // 消抖按下瞬间的电压 
        if (HAL_GPIO_ReadPin(KEY1_GPIO_Port, KEY1_Pin) == GPIO_PIN_RESET) 
        { 
            HAL_GPIO_TogglePin(LED_GPIO_Port, LED_Pin); // 翻转LED
            while(HAL_GPIO_ReadPin(KEY1_GPIO_Port, KEY1_Pin) == GPIO_PIN_RESET); // 等待高电平按键松开  
            delay_ms(15);// 消抖松开时瞬间的电压  
        } 
    } 
} 
```

 

**ISR_callback.h**
