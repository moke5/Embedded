### **四、教学内容**

**4.1 裸机调度背景**

在STM32F103等Cortex-M平台上，不使用RTOS时，常用两种调度模型：

- **前后台系统**（中断 + 主循环）

- **时间片轮询**（周期任务）

本课程实现的是一个**结合事件驱动与时间片轮询**的轻量级调度框架，适用于中等复杂度的嵌入式应用。

**4.2 事件队列模块（event.c/h）**

**4.2.1 设计目标**

- 提供**异步事件传递**机制，将中断发生的“事件”缓存，供主循环处理

- 避免在中断中执行耗时操作，将处理推迟到任务上下文

**4.2.2 数据结构**

```C
typedef struct {
    event_type_t type;   // 事件类型
    uint32_t     arg;    // 附加参数
} event_t;
 
static event_t s_queue[EVT_QUEUE_SIZE];  // 环形缓冲区
static volatile uint8_t s_head;          // 消费指针
static volatile uint8_t s_tail;          // 生产指针
```

**4.2.3 环形缓冲区原理**

在通信程序中，经常使用环形缓冲器作为数据结构来存放通信中发送和接收的数据。环形缓冲区是一个先进先出的循环缓冲区。

![img](./img/56814.png)

- 缓冲区容量为EVT_QUEUE_SIZE

- 入队：s_tail = (s_tail + 1) % EVT_QUEUE_SIZE

- 出队：s_head = (s_head + 1) % EVT_QUEUE_SIZE

- 满条件：(s_tail + 1) % EVT_QUEUE_SIZE == s_head（**留一个空位**以区分空/满）

- 空条件：s_head == s_tail

**4.2.4 安全访问队列**

- 所有公共函数内部均**关中断**（__disable_irq）操作指针，防止中断抢占破坏一致性

- 支持**多生产者**（多个中断源）和**单消费者**（主循环）

**4.2.5 队列满策略**

- 丢弃新事件（而非覆盖旧事件），保证已投递事件不被丢失，适用于“最新事件不重要”的场景。

**4.3 任务调度器模块（scheduler.c/h）**

**4.3.1 设计目标**

- 提供**周期任务**调度能力，避免主循环手写多个标志和延时

- 支持**动态注册**任务，简化业务扩展

- 空闲时进入低功耗，降低系统功耗

**4.3.2 数据结构**

```C
typedef void (*task_func_t)(void);
typedef struct {
    task_func_t func;       // 任务函数指针
    uint32_t    period_ms;  // 执行周期（ms）
    uint32_t    last_ms;    // 上次执行时间戳
} task_t;
 
static task_t s_task_table[SCHED_TASK_MAX_NUM];
static uint8_t s_task_cnt;
```

**4.3.3 调度算法**

- 主循环for(;;)中依次扫描所有注册任务

- 获取当前HAL_GetTick()

- 若(now - last_ms) >= period_ms（或period_ms==0始终执行），则调用任务函数并更新last_ms

- **关键**：now - last_ms利用无符号整数溢出特性，即使now回绕（约50天后）仍能正确判断

**4.3.4 低功耗集成**

- 一轮扫描后执行__wfi()（Wait For Interrupt）

- CPU暂停，直到任何中断（SysTick、外设中断）唤醒

- 唤醒后继续下一轮扫描，实现“无事则休眠”

**4.4 事件与调度器的协作流程**

```C
中断服务程序              主循环（调度器）
    |                          |
    | event_post()             | for(;;) {
    |  (关中断写队列)           |   扫描任务
    |                          |   task1: event_get() → 处理事件
    |                          |   task2: ...
    |                          |   __wfi()  // 等待中断唤醒
    |                          | }
 
```

- 中断只负责**投递事件**，不处理具体业务

- 主循环任务通过event_get()消费事件，执行对应动作

- 调度器周期性唤醒，保证事件得到及时处理

**4.5 关键编程要点**

1. **任务函数不能阻塞**（如HAL_Delay），否则影响其他任务和事件响应

1. **事件类型扩展**：在event_type_t枚举末尾添加，不影响已有代码

1. **队列大小选择**：根据中断频率和任务处理速度权衡，避免频繁丢事件

1. **中断优先级**：确保SysTick中断优先级不低于其他中断，保证调度时间基准

**6.3.1 初始化流程**

**app_main.c**：

```C
#include "main.h"
#include "app_main.h"
#include "app_debug.h" /* app_debug_init */
#include "app_led.h"   /* app_led_init / app_led_poll */
#include "app_key.h"   /* app_key_init / app_key_poll */
#include "app_co2.h"   /* app_co2_init / app_co2_poll */

/**
 * @brief  应用层主函数
 *
 * @note   由 main() 调用，内部启动调度器后永不返回。
 *         仅做初始化与任务注册，不包含任何业务处理代码。
 */
void app_main(void)
{
    	/* ===== 1. 初始化中间件 ===== */
    	event_init(); /* 事件队列清空 */
    
    	/* ===== 2. 初始化业务模块 ===== */
    	app_debug_init(); /* 调试串口 USART1 接收启动 */
    	app_led_init();	  /* LED 硬件初始化 + 上电自检 */
    	app_key_init();	  /* 按键硬件初始化 + 状态清零 */
    	app_co2_init();	  /* CO2 传感器初始化（串口2接收启动） */
    
    	/* ===== 3. 注册周期任务到调度器 ===== */
    	scheduler_init();
    	scheduler_add_task(app_key_poll, 10); /* 按键扫描：10ms 周期  */
    	scheduler_add_task(app_led_poll, 2000); /* LED 刷新 ：2000ms 周期  */
    	scheduler_add_task(app_co2_poll, 100); /* CO2 读取 ：100ms 周期 */
    
    	/* ===== 4. 启动调度器（永不返回，空闲时 __wfi 低功耗）===== */
    	scheduler_run();
}
```

**app_key.c关键代码**：

```C
/**
 * @brief  按键扫描周期任务（由调度器调用）
 * @note   分别扫描 KEY1 / KEY2，做消抖与边沿检测，按下瞬间投递事件
 */
void app_key_poll(void)
{
    /* 扫描 KEY1：按下时投递 EVT_KEY1_PRESSED（启动 CO2 采集） */
    app_key_scan_one(KEY1, &s_key1_debounce, &s_key1_pressed, EVT_KEY1_PRESSED);
 
    /* 扫描 KEY2：按下时投递 EVT_KEY2_PRESSED（停止 CO2 采集） */
    app_key_scan_one(KEY2, &s_key2_debounce, &s_key2_pressed, EVT_KEY2_PRESSED);
}
 
/* ============================ 内部函数实现 ============================ */
/**
 * @brief  单个按键的消抖与边沿检测
 * @param  key_num  按键编号（KEY1 / KEY2）
 * @param  debounce 指向该按键消抖计数器的指针
 * @param  pressed  指向该按键已按下标志的指针
 * @param  evt      该按键按下时要投递的事件类型
 * @note   消抖算法：
 *         - 连续 APP_KEY_DEBOUNCE_CNT 次检测到按下才确认有效；
 *         - 确认后仅在"首次"投递事件（边沿触发），之后按住不再重复投递；
 *         - 释放后复位计数器与标志，等待下一次按下。
 */
static void app_key_scan_one(uint32_t key_num,
                             uint8_t *debounce,
                             uint8_t *pressed,
                             event_type_t evt)
{
    uint32_t sta;
 
    /* 读取当前按键电平状态 */
    sta = key_read(key_num);
 
    if (sta == KEY_STA_PRESSED) {
        /* 当前检测到按下 */
        if (*debounce < APP_KEY_DEBOUNCE_CNT) {
            /* 消抖计数未满，继续累计 */
            (*debounce)++;
        } else if (*pressed == 0) {
            /* 消抖通过且尚未触发过本次按下 → 边沿触发，投递事件 */
            *pressed = 1;
            event_post(evt, 0);
        }
        /* 已触发过本次按下，按住不松开不再重复投递 */
    } else {
        /* 当前检测到释放，复位消抖计数与按下标志 */
        *debounce = 0;
        *pressed  = 0;
    }
}
```

 *
 * @param  huart 触发回调的串口句柄

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    /* USART1 接收完成：转发给 app_debug 模块，置位接收结束标志 */
    if (huart->Instance == USART1)
        app_debug_on_rxcplt();
}
 
/**
 * @brief  UART 接收事件回调（收到指定长度或检测到空闲时由 HAL 调用）
 *
 * @param  huart 触发回调的串口句柄
 * @param  Size  本次实际接收到的字节数
 */
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    /* USART1 接收事件：交给 app_debug 模块记录字节数、置标志并重启接收 */
    if (huart->Instance == USART1)
    {
        app_debug_on_rx_event(Size);
    }
 
    /* USART2 连接 CO2 传感器：
     *   1. 驱动层保存本次数据帧并重启下一次接收；
     *   2. 向事件队列投递 EVT_CO2_FRAME_READY，通知应用层有新数据。
     */
    if (huart->Instance == USART2)
    {
        co2_rx_event_handler(Size);
        event_post(EVT_CO2_FRAME_READY, (uint32_t)Size);
    }
}

### **七、总结与思考**

- **优势**：代码简洁、占用资源少（仅需数十字节RAM）、实时性可控，适合资源受限MCU

- **局限**：非抢占，长任务会堵塞所有；时间片精度依赖SysTick（1ms）

- **改进方向**：可增加任务优先级、动态调整周期、支持软件定时器等

- **扩展**：可结合DMA、FIFO等实现更复杂的数据流处理

# 生产者与消费者

## **一、生产者、消费者模型基础概念**

**（嵌入式事件队列场景）**

#### **1. 通用定义**

生产者-消费者（Producer-Consumer）是经典同步模型，解决**两类主体速率不匹配、数据交互冲突**问题

1. **生产者 Producer**：负责产生数据/事件，把数据存入缓冲区；

​	产生速度快、触发随机，不能阻塞等待处理完成。

2. **缓冲区 Buffer**：中间缓存载体（本项目为环形FIFO事件队列），解耦生产、消费速度；

3. **消费者 Consumer**：从缓冲区取出数据，完整执行业务处理；处理耗时更长，不需要实时立刻响应。

#### **2. 结合本项目 event 模块对应角色**

**生产者（多生产者）**

所有中断服务程序：外部按键中断、串口接收中断、传感器数据中断

- 特点：中断触发随机、执行时间极短；

- 行为：只调用 `event_post()`，快速写入事件到环形队列，立刻退出中断，不做任何业务运算。

**缓冲区**

`event_t s_queue[EVT_QUEUE_SIZE]` 环形FIFO数组

作用：缓存来不及处理的中断事件，隔离中断（前台）与主循环（后台）。

**消费者（单消费者）**

调度器中0周期任务 `task_event_handler`（主循环上下文）

- 特点：运行在后台，无中断限时约束；

- 行为：循环调用 event_get() 读取队列，匹配事件类型执行完整业务（打印、传感器控制、状态切换）。

#### **3. 核心解决两大问题**

1. **速率不匹配**：中断瞬间大量产生事件，后台处理速度慢，缓冲区临时存放，避免丢失；

1. **上下文竞争冲突**：中断（生产者）、主循环（消费者）同时操作缓冲区头尾指针，通过关中断临界区保证数据安全。

#### **4. 本模型约束：多生产者、单消费者**

- 多生产者：多个中断都可以投递事件写入队列；

- 单消费者：只有主循环一个任务读取队列； 代码中仅用**关中断**即可完成同步，不需要复杂信号量/互斥锁，适配裸机无OS环境。

**2.2 生产动作细节图（event_post 写入流程）**

```C
中断触发（生产者）
        │
        ▼
关闭全局中断 __disable_irq() 【临界区，防止抢占错乱指针】
        │
        ▼
判断队列是否已满：(tail+1)%size == head
    ├─是：丢弃本次事件，直接开中断退出（保旧丢新）
    └─否：将事件type+arg写入s_queue[tail]，更新tail指针
        │
        ▼
开启全局中断 __enable_irq()
        │
        ▼
退出中断，生产完成
 
```

**2.3 消费动作细节图（event_get 读取流程）**

```C
调度器循环执行消费者任务
        │
        ▼
关闭全局中断 __disable_irq()
        │
        ▼
判断队列是否为空：head == tail
    ├─是：返回空事件EVT_NONE
    └─否：读取s_queue[head]事件，更新head指针
        │
        ▼
开启全局中断 __enable_irq()
        │
        ▼
拿到事件，执行业务处理（耗时操作无限制）
 
```

## **三、通俗生活化类比**

奶茶店场景完美对应生产者消费者：

1. **生产者（顾客）**：不断进店点单，随机、短时间完成下单；对应中断随机产生事件；

1. **缓冲区（订单排队小票）**：前台小票缓存所有订单；对应环形队列；

1. **消费者（奶茶店员）**：按顺序一张一张制作奶茶，制作慢；对应主循环后台处理业务。

- 顾客不会等奶茶做完再走（中断不能阻塞），只下单；

- 店员空闲时慢慢处理堆积订单（后台循环消费事件）；

- 小票打印满了就不再接单（队列满丢弃新事件）。

**四、嵌入式裸机场景优缺点**

**优点**

1. 前后台完全解耦，中断只做快速标记，符合“中断快进快出”规范；

1. 缓存削峰，突发大量中断不会直接卡死系统；

1. 裸机无操作系统，仅用关中断实现同步，资源占用极小。

**局限**

1. 本代码为「保旧丢新」策略，缓冲区满载时新事件直接丢弃；

1. 缓冲区长度固定，高频中断场景需要增大数组容量。
