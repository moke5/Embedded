# 定时器

[toc]

## 1 系统定时器

### 1.1 概述

  ARM Cortex-M4集成了一个SysTick，它提供了一种简单的、**24位**写清零（clear-on-write）、递减的、计数值减到零后自动重载(wrap-on-zero)的计数器，该计数器带有灵活的控制机制。

  SysTick其实就是一个定时器而已，只是它放在了NVIC中，主要的目的是为了给操作系统提供一个硬件上的中断（也称作“滴答中断”）。

  那么什么是滴答中断呢？这里来简单地解释一下。当操作系统进行运转的时候，也会有“心跳”。它会根据“心跳”的节拍来工作，把整个时间段分成很多小小的时间片，每个任务每次只能运行一个“时间片”的时间长度就得退出给别的任务运行，这样可以确保任何一个任务都不会霸占整个系统不放。或者把每个定时器周期的某个时间范围赐予特定的任务等，还有操作系统提供的各种定时功能，都与这个滴答定时器有关。

  因此，需要一个定时器来产生周期性的中断，而且最好还让用户程序不能随意访问它的寄存器，以维持操作系统“心跳”的节律。

  只要不把它在SysTick控制及状态寄存器中的使能位清除，就永不停息。

### 1.2 频率

  物质在1s内完成周期性变化的次数叫做频率，常用f表示。为了纪念德国物理学家赫兹的贡献，人们把频率的单位命名为赫兹，简称“赫”，符号为HZ。

```
  周期与频率的关系：f=1/T（其中f为频率，T为周期）。
```

  周期，物体作往复运动或物理量作周而复始的变化时，重复一次所经历的时间。物体或物理量（如交变电流、电压等）完成一次振动（或振荡）所经历的时间。

## 2 代码分析

### 2.1 SysTick初始化

  stm32f4xx_hal.c中HAL_Init函数调用HAL_InitTick函数，对系统定时器的初始化。

```C
HAL_StatusTypeDef HAL_Init(void)
{
    ......
    HAL_InitTick(TICK_INT_PRIORITY);//TICK_INT_PRIORITY初值为0
    ......
}
```

  而HAL_InitTick函数内部调用HAL_SYSTICK_Config配置系统定时器的定时中断频率(默认为1000Hz)，调用HAL_NVIC_SetPriority函数配置其中断抢占优先级与响应优先级。

```C
/** @defgroup HAL_TICK_FREQ Tick Frequency
  * @{
  */
typedef enum {
  HAL_TICK_FREQ_10HZ         = 100U,
  HAL_TICK_FREQ_100HZ        = 10U,
  HAL_TICK_FREQ_1KHZ         = 1U,
  HAL_TICK_FREQ_DEFAULT      = HAL_TICK_FREQ_1KHZ
} HAL_TickFreqTypeDef;

HAL_TickFreqTypeDef uwTickFreq = HAL_TICK_FREQ_DEFAULT;  /* 1KHz */

__weak HAL_StatusTypeDef HAL_InitTick(uint32_t TickPriority)
{
  /* Configure the SysTick to have interrupt in 1ms time basis

     180000000/1000/1=180000，也就是系统定时器的计数范围179999~0，即从179999开始计数到0结束，共180000个节拍，就是1ms时间的到达。
  */
  if (HAL_SYSTICK_Config(SystemCoreClock / (1000U / uwTickFreq)) > 0U) {
    return HAL_ERROR;
  }

  /* 配置系统定时器的抢占优先级 */
  if (TickPriority < (1UL << __NVIC_PRIO_BITS)) {
    HAL_NVIC_SetPriority(SysTick_IRQn, TickPriority, 0U);
    uwTickPrio = TickPriority;
  } else {
    return HAL_ERROR;
  }

  /* Return function status */
  return HAL_OK;
}
```

### 2.2 SysTick中断处理

  当SysTick的计数值自减为0时，会触发中断请求，进入SysTick_Handler函数执行中断处理。该函数会调用HAL_IncTick函数执行uwTick时基值自加（默认自加1）。

**SysTick_Handler**

```C
/**
  * @brief This function handles System tick timer.
  */
void SysTick_Handler(void) {
    //每触发一次中断，就自加1次节拍
    HAL_IncTick();
}
```

**HAL_IncTick**

```C
__weak void HAL_IncTick(void) {
  //uwTickFreq默认值为1（来自枚举体中的HAL_TICK_FREQ_1KHZ）
  uwTick += uwTickFreq;
}
```

## 3 延时函数

### 3.1 毫秒延时

  HAL库在SysTick的基础上编写了毫秒级的延时函数HAL_Delay，该函数使用了__weak关键字修饰，意味着该函数可被重写。

```C
/**
  * @brief This function provides minimum delay (in milliseconds) based 
  *        on variable incremented.
  * @note In the default implementation , SysTick timer is the source of time base.
  *       It is used to generate interrupts at regular time intervals where uwTick
  *       is incremented.
  * @note This function is declared as __weak to be overwritten in case of other
  *       implementations in user file.
  * @param Delay specifies the delay time length, in milliseconds.
  * @retval None
  */
__weak void HAL_Delay(uint32_t Delay)
{
  //保存进入HAL_Delay函数时的节拍初值
  uint32_t tickstart = HAL_GetTick();

  //需要延时的时间
  uint32_t wait = Delay;

  //......

  //查询当前得到的节拍值与进入HAL_Delay函数时的节拍初值之差是否已经达到需要的延时时间wait
  //如果是，则跳出该循环，HAL_Delay延时结束。
  while((HAL_GetTick() - tickstart) < wait)
  {
  }
}
```

  HAL_Delay函数使用查询法，利用Systick的计数值的自减特点，调用HAL_GetTick函数实时得到计数值，判断差值最后得到延时的时间。

```C
/**
  * @brief Provides a tick value in millisecond.
  * @note This function is declared as __weak to be overwritten in case of other 
  *       implementations in user file.
  * @retval tick value
  */
__weak uint32_t HAL_GetTick(void) {
    //返回节拍值
    return uwTick;
}
```

### 3.2 微秒延时

  HAL库现目前只提高了HAL_Delay函数实现毫秒级的延时，却没有提供微秒级的延时，在控制类总线中，微秒级的延时会频繁的使用，因此，需要再单独编写微秒的延时函数，详细代码如下。

```C
void delay_us(uint32_t nus) {
	uint32_t told,tnow,tcnt=0;
	uint32_t temp=0;
	uint32_t reload=SysTick->LOAD;			//系统定时器的重载值
	uint32_t ticks=nus*(SystemCoreClock/1000000);	//总共要等待的滴答数目
	told=SysTick->VAL;        			//刚进入时的计数器值
	while(1) {
		//获取当前计数值
		tnow=SysTick->VAL;
		if(tnow!=told) {
			//SYSTICK是一个递减的计数器
			if(tnow<told) tcnt+=told-tnow;        //情况1			
			else tcnt+=reload-tnow+told; //情况2
			told=tnow;
			//时间超过/等于要延迟的时间，则退出。
			if(tcnt>=ticks) break;	
		}
		temp=SysTick->CTRL;
		//若系统定时器中途关闭了，跳出循环
		if((temp & 0x01)==0) break;
	}
}
```

假设重载值为99，则计数器计数范围（99 ~ 0），延时时间的情况1与情况2示例如下图。


![img](./img/rBJlJmJhDd6AFUNKAADNdx_pAcQ134.gif)

**情况1分析**

  told=2,tnow=1,tcnt=told-tnow=2-1=1，即1个节拍。

**情况2分析**

  told=2,tnow=97（注：视频中的tnow为99，应为97）,tcnt=reload-tnow+told=99-97+2=4，即4个节拍。

  以0作为分割点，reload-tnow求出右半部分的计数值，told则为左半部分的计数值，最后得出就是累计得到的总计数值了。

  为统一代码风格，毫秒级的延时函数亦可编写如下。

```C
void delay_ms(uint32_t nms) {
    HAL_Delay(nms);
}
```

# 外设定时器

## 1 外设定时器

### 1.1 概述

  前面章节讲解到的系统定时器只具有计数功能，若要实现脉冲输出、脉冲计数等功能，需要使用到外设定时器。对于STM32F4系列芯片，其外设定时器数目可到达14个。该章节选择TIM3作为讲解。

  TIM3属于通用定时器，其包含一个 16 位自动重载计数器，有些定时器是32位自动重载计数器，如定时器2和定时器5。该计数器由可编程预分频器驱动。它们可用于多种用途，包括测量输入信号的脉冲宽度（输入捕获）或生成输出波形（输出比较和PWM）。
使用定时器预分频器和 RCC 时钟控制器预分频器，可将脉冲宽度和波形周期从几微秒调制到几毫秒。

  这些定时器彼此完全独立，不共享任何资源。

### 1.2 特性

**通用 TIM3定时器具有以下特性：**

- 16 位递增、递减和递增/递减自动重载计数器。
- 16 位可编程预分频器，用于对计数器时钟频率进行分频 （即运行时修改）分频系数介于 1 到 65536 之间。
- 多达 4 个独立通道（此应用于无人机的电机控制非常实用，输出4路稳定的频率），可用于：
    - 输入捕获
    - 输出比较
    - PWM 生成
    - 单脉冲模式输出
- 使用外部信号控制定时器且可实现多个定时器互连的同步电路。
- 发生如下事件时生成中断/DMA 请求：
    - 更新：计数器上溢/下溢、计数器初始化（通过软件或内部/外部触发）
    - 触发事件（计数器启动、停止、初始化或通过内部/外部触发计数）
    - 输入捕获
    - 输出比较
- 支持定位用增量编码器和霍尔传感器电路
- 外部时钟触发输入或逐周期电流管理（旨在实现原边侧的逐周期保护，在有输入电压浪涌，输出短路等场合可以实现快速响应与保护）

### 2.2 代码分析

**1、TIM3初始化**

```C
TIM_HandleTypeDef htim3;

/* TIM3 init function */
void MX_TIM3_Init(void)
{
  TIM_ClockConfigTypeDef sClockSourceConfig = {0};
  TIM_MasterConfigTypeDef sMasterConfig = {0};
  
  htim3.Instance = TIM3;//定时器3实例，实际上提供定时器3寄存器基址
  htim3.Init.Prescaler = 9000-1;//预分频值
  htim3.Init.CounterMode = TIM_COUNTERMODE_UP;//向上计数模式
  htim3.Init.Period = 10000-1;//计数值
  htim3.Init.ClockDivision = TIM_CLOCKDIVISION_DIV1;//时钟分频，即再次进行分频
  htim3.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_ENABLE;//使能自动重新预加载，即计数值减为0后，自动被赋予初始计数值
  
  /* 初始化TIM3时基 */
  if (HAL_TIM_Base_Init(&htim3) != HAL_OK) {
    Error_Handler();
  }
  
  /* TIM3使用内部时钟源 */
  sClockSourceConfig.ClockSource = TIM_CLOCKSOURCE_INTERNAL;
  if (HAL_TIM_ConfigClockSource(&htim3, &sClockSourceConfig) != HAL_OK) {
    Error_Handler();
  }
  
   /* 该模式常用于多定时器同步，选择主模式下将要发送到从定时器以实现同步的信息*/ 
   //TIMx_EGR 寄存器中的 UG 位(重新初始化计数器并生成寄存器更新事件)用作触发输出 (TRGO)。
  sMasterConfig.MasterOutputTrigger = TIM_TRGO_RESET; 
  //此设置适用于单个外部事件对多个定时器进行同步的情况，目前不执行任何操作。
  sMasterConfig.MasterSlaveMode = TIM_MASTERSLAVEMODE_DISABLE;
  if (HAL_TIMEx_MasterConfigSynchronization(&htim3, &sMasterConfig) != HAL_OK) {
    Error_Handler();
  }
  
 	//手动添加：清除时间更新标志位
  __HAL_TIM_CLEAR_IT(&htim3, TIM_IT_UPDATE);
  
	//手动添加：开启定时器更新中断
	HAL_TIM_Base_Start_IT(&htim3);    
}
```

*分析*

  MX_TIM3_Init函数内部调用了HAL_TIM_Base_Init用于初始化定时器3的时基。

  其输入时钟频率为=（ APB1的时钟频率 x 2 ) / 分频值=（45MHz x 2）/ 9000 =10000Hz。只要定时器3对内部时钟计数累计为10000个，就是1秒时间的到达。

  若要求定时器3的定时1秒，则进行10000次计数，即计数值Period 需设置为9999，从0计数到9999，共10000次计数。

  若要求定时器3的周期性中断，AutoReloadPreload需设置为TIM_AUTORELOAD_PRELOAD_ENABLE。

  最后调用HAL_TIM_Base_Start_IT函数开启定时器3中断触发。

# PWM

## 1 PWM概述

1、定义

  **PWM（Pulse Width Modulation）**，**脉冲宽度调制**能利用微处理器的数字输出来对模拟电路进行控制的一种非常有效的技术，广泛应用在从测量、通信到功率控制与变换的许多领域中,例如电机转速的控制、灯光亮度的控制等。

2、优点

  PWM的一个优点是从**处理器到被控系统信号都是数字形式的**，无需进行数模转换，让信号保持为数字形式可将噪声影响降到最小。噪声只有在强到足以将逻辑1改变为逻辑0或将逻辑0改变为逻辑1时，也才能对数字信号产生影响。

  对噪声抵抗能力的增强是PWM相对于模拟控制的另外一个优点，而且这也是在某些时候将PWM用于通信的主要原因。从模拟信号转向PWM可以极大地延长通信距离。在接收端，通过适当的RC或LC网络可以滤除调制高频方波并将信号还原为模拟形式。

3、占空比

  **占空比是指在一个脉冲周期中，通电时间相对于总时间所占的比例。**占空比(Duty Ratio)在电信领域中有如下含义：例如脉冲宽度1μs，信号周期4μs的脉冲序列，占空比为25%。

> 占空比 = t1 / T = 1us / 4us = 25%


![img](./img/rBJlJmJmi06ATjm0AABlucBaCHg240.png)

  在有些技术资料中，占空比控制也被称为脉宽调制技术。是通过电子控制单元对加在工作执行元件上一定频率的电压信号进行脉冲宽度的调制，即占空比控制，以实现对元件工作状况的精准、连续控制。

  由于电压=电流×电阻。电控执行元件多数为带有一定电阻值的线圈或导体，在很多情况下，电源的电动势也是基本恒定不变化的，所以简单的控制线路只能实现接通工作元件电路或切断工作元件线路这两种工况，即通断，是无法实现无极调控。而占空比控制技术是利用控制开关通断的比例，实现对工作元件上电压信号的电压平均值的控制，从而最终实对流经工作元件的电流控制。

**通俗的理解**

脉冲：方波，频率(freq)

宽度：高电平的宽度，占空比(duty)

（1）工作频率

  要实现精确的占空比控制，该电路必须有**恒定的工作频率**做保证。其实频率固定，也就是工作电路周期固定。因为，占空比控制的电路接通率是建立在恒定工作周期上的，如果电子控制模块控制电路的周期不能保证恒定，那么所谓的占空比控制是毫无意义的。

（2）工作电压

  工作电压是加在**执行元件上的恒定电压**，有3.3V或5V等，根据工作元件的阻抗而定。用示波器可以清楚地看到恒定不变的工作电压。

（3）平均工作电压

  指经过占空比调制后在一个周期中加在工作电路上的电压平均值，这才是真正用于驱动工作执行元件的电压。只要用简单的万用表就可以检测到平均工作电压。

（4）脉冲宽度

  指在一个工作周期中，电路被接通或工作的真实时间。

5、分类

  占空比控制系统根据执行元件的位置可分为正向占空比控制和负向占空比控制。一般控制执行元件供能端的称为正向占空比控制，反之控制接地端的称为负向占空比控制。

  高电平“1”表示有效，还是低电平“0”表示有效都是可因人而设。如果设定高电平“1”有效，低电平“0”无效则叫正逻辑，如果反过来，设定低电平“0”有效，高电平“1”无效时，则为负逻辑。一般情况下，没有加以特殊说明，均采用正逻辑关系。

## 2 PWM模式

### 2.1 原理

**频率**

在预分频系数确定的条件下，PWM模式的信号频率是由自动重装载寄存器(ARR)来确定的，占空比则由比较寄存器(CCR)来确定。

在使用PWM模式时，我们只需要设置预分频系数PSC，自动重装载值ARR，即可确定PWM具体频率，即 PWM频率 =（定时器时钟源频率）/((ARR+1)*(PSC+1))。

$$ f_{\text{PWM}} = \frac{f_{\text{TIM}}}{(\text{ARR}+1)(\text{PSC}+1)}, \quad \begin{cases} f_{\text{PWM}} & \text{：PWM输出频率} \\ f_{\text{TIM}} & \text{：定时器时钟源频率} \\ \text{ARR} & \text{：自动重装载寄存器值} \\ \text{PSC} & \text{：预分频寄存器值} \end{cases} $$

这里以PWM1的递增计数方式为例，若定时器时钟源频率设置为90MHz，那么当ARR取99，PSC取8999的时候，PWM的频率即为100Hz。

**有效电平**

PWM模式分为两种，PWM1和PWM2，都可以设置计数器递增计数或者递减计数，计数器的值(CNT)与比较寄存器(CCR)关系具体如下表：

| 模式 |                     说明                      |
| :--: | :-------------------------------------------: |
| PWM1 | CNT < CCR，输出通道为有效状态，否则为无效状态 |
| PWM2 | CNT < CCR，输出通道为无效状态，否则为有效状态 |

当计数值小于设置的比较值时，PWM输出引脚输出为高电平，当计数值大于等于比较值时，PWM输出引脚输出为低电平，当计数值至自动重载值时，计数器产生上溢事件，计数器的值更新为0，以此往复。

利用计数值与比较值的关系，可以输出任意占空比的脉冲。

```
占空比=比较值/(最大计数值+1)
```

**1、输入捕获回调函数**

  在HAL_TIM_IC_CaptureCallback回调函数完成一个完整脉冲捕获，依次记录上升沿、下降沿、上升沿所对应的计数值，详细代码如下：

```C
__IO uint16_t g_pwm_cv_tbl[3]={0};
__IO uint16_t g_pwm_cv_sta=0;

void HAL_TIM_IC_CaptureCallback(TIM_HandleTypeDef *htim)
{

  if (htim->Channel == HAL_TIM_ACTIVE_CHANNEL_2) {
	  switch(g_pwm_cv_sta) {
		  case 0: {
				/* 首次检测到上升沿 */
				if(HAL_GPIO_ReadPin(GPIOB,GPIO_PIN_7) == GPIO_PIN_SET) {
					/* 记录输入捕获值 */
					g_pwm_cv_tbl[0]=HAL_TIM_ReadCapturedValue(&htim4,TIM_CHANNEL_2);
					
					/* 输入捕获状态标记为1 */
					g_pwm_cv_sta=1;				
				}
		  }break;
		  case 1: {
			    /* 检测到下降沿 */
				if(HAL_GPIO_ReadPin(GPIOB,GPIO_PIN_7) == GPIO_PIN_RESET) {
					/* 记录输入捕获值 */
					g_pwm_cv_tbl[1]=HAL_TIM_ReadCapturedValue(&htim4,TIM_CHANNEL_2);
					
					/* 输入捕获状态标记为2 */
					g_pwm_cv_sta=2;				
				}
		  }break;	
		  case 2: {
				/* 再次检测到上升沿 */
				if(HAL_GPIO_ReadPin(GPIOB,GPIO_PIN_7) == GPIO_PIN_SET) {
					/* 记录输入捕获值 */
					g_pwm_cv_tbl[2]=HAL_TIM_ReadCapturedValue(&htim4,TIM_CHANNEL_2);
					
					/* 输入捕获状态标记为3，表示完整捕获到一个完整周期的脉冲 */
					g_pwm_cv_sta=3;				
				}
		  }break;
		  default:break;
	  }
  }
}
```

```C

// 实测：1ms误差±0.02ms，1000ms误差±15ms，满足外设控制需求 
void delay_ms(uint32_t ms) 
{ 
    volatile uint32_t i, j; 
    // 72MHz主频精准校准值，一行修改完成适配，核心逻辑不变 
    uint32_t calibrate = 8000;  // 该值严格对应72MHz下约1ms延时

            ; 
        } 
    } 
}
```

### **二、SysTick简介**

SysTick定时器，又名系统**定时器、滴答定时器**，是属于Cortex-M3内核中的一个外设，内嵌在NVIC中。系统定时器是一个**24bit的向下递减的计数器**。SysTick定时器的应用

1. 操作系统定时器：在RTOS（实时操作系统）中，SysTick定时器常被用作系统定时器，用于实现任务调度和定时器管理。
2. 软件定时器：在没有RTOS的情况下，也可以利用SysTick定时器实现简单的软件定时功能。
3. 周期性任务：可以用来定期执行一些周期性的任务，如采样ADC、刷新LCD显示等。

**2.3 时序图理解**

 💡

**发生中断间隔时间 = 一个脉冲时间 \* (重装载值  + 1)** 

注意：一个脉冲周期时间 =  1 / 频率 

根据公式，使用内核时钟 72MHz ，期待每间隔 1ms，发生一次中断：

```
重装载值 = 1ms * 72MHz - 1 = 72000  - 1 = 71999
```

注意：重装载的值不能超过 24bit 存储的范围，即不能超过16777215。

### **六、SysTick定时器实现us精度延时**

```C
void delay_us(uint32_t us) 
{ 
    uint32_t save_LOAD;   // 备份原SysTick->LOAD值 
    uint32_t target_ticks;// 目标us对应的SysTick重载值 
    
    // 1. 备份原始LOAD值（核心！延时结束必须恢复，否则HAL_Delay无法使用） 
    save_LOAD = SysTick->LOAD; 
    
    // 2. 计算目标us对应的重载值：SystemCoreClock(Hz) → 当前内核时钟的主频位72MHz，对应1us计数为72个脉冲 
    target_ticks = (1UL * SystemCoreClock / 1000000) * us; 
    
    // 3.关闭SysTick中断，CTRL寄存器的bit1清零
    SysTick->CTRL &=~0x02; 
    
    // 4. 配置SysTick为「目标us计数模式」，启动计数 
    SysTick->LOAD=target_ticks - 1; // 重载值=计数值-1,(999->0总共是1000个计数) 
    SysTick->VAL=0UL;               // 计数器清零，同时也会同步清空 SysTick->CTRL的COUNTFLAG标志位，立刻开始计数 
    
    // 5. 硬件等待：直到计数完成（COUNTFLAG置1） 
    while ((SysTick->CTRL&(1<<16))==0); 
    
    // 6. 完全复原：恢复原始LOAD值，保证SysTick原理周期1ms不变 
    SysTick->LOAD=save_LOAD; 
    SysTick->VAL=0; 
    
    // 7. 恢复SysTick中断（否则HAL_Delay无法使用） 
    SysTick->CTRL|=0x02; 
}
```

**注意：**重载值最大值为16777215，即该函数最大延时约233毫秒（内核时钟72MHz）。强烈建议延时 ms 时，用 HAL_Delay() 函数。

## PWM

### **一、PWM 概述**

脉冲宽度调制（Pulse Width Modulation，简称PWM）是一种电子信号控制技术，常用于模拟信号和数字信号之间的转换。

PWM是一种通过改变脉冲信号的宽度来编码模拟信号的技术。在PWM信号中，脉冲的频率通常是固定的，而脉冲的宽度（即高电平持续的时间）会根据需要改变。这种信号通常用于控制电机的速度、灯光的亮度等。

 

![img](./img/56926.gif)

 **关键参数**

- 频率（frequency）：PWM信号的重复速率，单位通常是赫兹（Hz）。

- 周期（period）：从一个脉冲开始到下一个相同脉冲开始的时间间隔。

- 占空比（duty）：在一个周期内脉冲高电平持续时间与整个周期时间的比例。

 

**应用场景**

PWM技术在很多领域都有广泛的应用，包括但不限于：

- 电机控制：通过改变PWM信号的占空比来控制直流电机的速度，或控制交流电机的转速和方向。

- **LED亮度调节**：通过改变PWM信号的占空比来调节LED灯的亮度。

- 电源管理：在开关电源中使用PWM来调节输出电压或电流。

- 音频放大器：某些音频放大器采用PWM技术来提高效率和减少失真。

- 加热元件控制：在温度控制系统中，PWM可以用来精确地控制加热元件的功率。

- 伺服控制：伺服电机通常通过接收特定频率和占空比的PWM信号来进行位置控制。

- 电池充电管理：PWM可以用于电池充电电路中的电流调节。

- 太阳能跟踪系统：PWM技术可以用来优化太阳能板对太阳光线的跟踪角度。

- 音频文件： 微软WAV音频文件格式， PWM信号

### **二、占空比**

上图展示 STM32 定时器 “**PWM1 模式 + 向上计数**” 的工作逻辑：

💡

- 计数器 CNT 从 0 递增至自动重装值 ARR 后重置为0

- 当 CNT < 比较值 CCR1 时，主输出 OC1 为高电平、互补输出 OC1N 为低电平

- 当 CNT≥CCR1 时，OC1 切换为低电平、OC1N 切换为高电平

**3.3 PWM周期计算**

💡

**PWM 周期 = 计数一次时间 \* 一个周期计数次数**

   **= 1 / CK_CNT频率 \*  （ARR + 1）**

例如：定时器时钟源频率为72MHz，预分频器寄存器PSC数值为 71，自动重装载寄存器ARR为 999

**PWM 周期 = 1 / (72MHz / (71 + 1) )   \* (999 + 1) = 1 / 1000Hz**

**PWM 频率 = 1 / PWM 周期 = 1KHz**

更容易理解的方法：

- 只要定时器进行1000000次计数，就是1秒时间的到达，频率为1Hz。

- 只要定时器进行100000次计数，就是0.1秒时间的到达，频率为10Hz。  

- 只要定时器进行10000次计数，就是0.01秒时间的到达，频率为100Hz。  

- 只要定时器进行1000次计数，就是0.001秒时间的到达，频率为1000Hz。  

为什么计数次数是ARR+1?看下图理解：

![img](./img/56939.png)

可以看到，定时器是从 0 开始计数，直到 ARR 值，这一过程包含了 “0 到 ARR” 共 (ARR+1) 个计数点。

**1. Mode：PWM mode 1**

- **功能**：PWM输出比较模式，分为PWM模式1、PWM模式2向上计数规则：

- PWM Mode1：CNT < CCR(Pulse) → 输出有效电平；CNT ≥ CCR → 输出无效电平

- PWM Mode2：CNT < CCR → 输出无效电平；CNT ≥ CCR → 输出有效电平

需要和【CH Polarity通道极性】搭配，共同决定引脚高低电平变化逻辑。

**2. Pulse (16 bits value)：0**

- **功能**：CCRx捕获比较寄存器**初始配置值**，决定PWM占空比

- 取值范围：0 ~ ARR（自动重装载寄存器数值）

- 占空比公式（Mode1 + CH Polarity=High）：占空比 = Pulse / (ARR+1)

- 补充：CubeMX仅设置上电初始占空比；代码运行时依靠__HAL_TIM_SET_COMPARE()动态修改该数值。

**3. Output compare preload：Enable（OCPE 输出比较预装载）**

- **功能**：控制CCR新值的加载时机
- Enable（开启，当前配置）：软件更新CCR后，新数值**暂存缓冲**，必须等到**定时器更新事件（CNT计数溢出）**，下一个PWM周期起点才生效。单个周期波形不会突变，输出波形平滑稳定。
- Disable（关闭）：CCR写入后立即生效。

⚠️联动规则：**Fast Mode开启时，会强制屏蔽本预装载功能**。两者不能同时生效。

**4. Fast Mode：Disable（OCxFE 输出比较快速模式）**

- **功能**：改变CCR更新生效逻辑，仅**边沿对齐向上计数PWM模式**可用，中心对齐模式无效
- Disable（关闭，当前配置）：遵循Output compare preload预装载规则；开启预装载时，CCR修改值等待周期结束生效。
- Enable（开启）：强制关闭CCR预装载机制；软件修改CCR后，**当前PWM周期立刻生效**，占空比响应速度最快；风险：同一周期波形可能出现畸变脉冲。

两者优先级：Fast Mode > Output compare preload

使用建议：普通LED、舵机 → FastMode=Disable；FOC电机、开关电源实时闭环控制 → FastMode=Enable

**5. CH Polarity：High（通道输出极性）**

- **功能**：定义上面PWM模式中描述的【有效电平】

- High：满足匹配条件时，引脚输出高电平

- Low：满足匹配条件时，引脚输出低电平

示例：Mode1 + Polarity=High

CNT < Pulse → 高电平；CNT ≥ Pulse → 低电平

**6. CH Idle State：Reset（通道空闲状态）**

- **功能**：**仅高级定时器TIM1 / TIM8有效；TIM2/TIM3/TIM4通用定时器无此功能，配置无效！** 空闲场景：调用HAL_TIM_PWM_Stop()关闭PWM输出、定时器停止工作后，通道引脚保持的固定电平

- Reset：空闲状态引脚输出**低电平**（当前配置）

- Set：空闲状态引脚输出**高电平**

区分两个容易混淆概念：

2. CH Polarity：**PWM正常运行时**，波形有效电平

2. CH Idle State：**定时器停止PWM输出后**，引脚静态电平

典型场景：电机驱动（TIM1高级定时器），停止输出时强制拉低引脚，防止误触发功率管。

 

**4.2.2 边沿对齐与中心对齐模式（知识延伸）**

| **特性**   | **边沿对齐（向上计数）**     | **中心对齐模式**       |
| ---------- | ---------------------------- | ---------------------- |
| 计数方式   | 单向递增：0→ARR              | 双向往返：0→ARR→0      |
| 周期长度   | ARR+1 个计数脉冲             | 2×(ARR+1) 个计数脉冲   |
| 脉冲对称性 | 不对称                       | 对称                   |
| Fast Mode  | 可用                         | 不可用                 |
| 典型场景   | 舵机、LED 调光、普通开关电源 | BLDC 无刷电机 FOC 驱动 |

 

**4.2.2.1 边沿对齐-向上计数模式**

![img](./img/56943.png)

**基础条件**

定时器：**边沿对齐，向上计数模式**

ARR=8，CCRx=4

计数序列：0 → 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 0 → 1……

CNT计数到达ARR(8)后产生更新事件，计数器清零回到0，开启下一个周期。

 

**1. 各信号含义**

**（1）计数器寄存器 CNT**

单向递增计数：从0一直加到ARR，溢出自动归零；

一轮 0→8 = **1个完整PWM周期**。

**（2）OCxREF 内部参考波形**

当前配置：**PWM Mode 1**

规则：

- CNT < CCRx(4)  → OCxREF = 高电平

- CNT ≥ CCRx(4) → OCxREF = 低电平

对照波形：

0~4：OCxREF高

4~8：OCxREF低

CNT=8清零回到0，波形循环。

OCxREF是片内基准信号，再经过【CH Polarity通道极性】翻转，才输出到GPIO引脚。

**（3）CCxIF 捕获比较中断标志（TIM_SR寄存器）**

触发条件：**CNT == CCRx(4) 的瞬间，硬件自动置1**

向上计数模式只有**一次匹配点（CNT上升经过4）**

👉 **一个PWM周期只会产生1次CCxIF标志**。

 

**4.2.2.2 STM32定时器中心对齐 PWM（知识延伸）**

![img](./img/56944.png)

**基础条件先说明**

图配置：中心对齐计数，ARR=8，CCRx=4

计数序列：0→1→2→3→4→5→6→7→8→7→6→5→4→3→2→1→0

**1. CMS（Center-aligned mode selection）**

寄存器位：TIMx_CR1.CMS[1:0]，**中心对齐模式选择位**

| CMS[1:0] | 模式                                                   |
| -------- | ------------------------------------------------------ |
| 00       | **边沿对齐模式（向上 / 向下计数）**                    |
| 01       | 中心对齐模式 1：**仅 CNT 递减匹配时，置位 CCxIF 标志** |
| 10       | 中心对齐模式 2：**仅 CNT 递增匹配时，置位 CCxIF 标志** |
| 11       | 中心对齐模式 3：**递增、递减两次匹配，都会置位 CCxIF** |

图上标注：

- CMS=01：只有**下降阶段（8→0）** CNT==CCR(4) 产生CCxIF中断标志

- CMS=10：只有**上升阶段（0→8）** CNT==CCR(4) 产生CCxIF中断标志

- CMS=11：上升、下降两次经过CCR=4，**两次都会触发CCxIF**

通俗理解：CMS 决定**一个PWM周期内，比较匹配中断触发几次、在哪一侧触发**。

**2. CCxIF（Capture/Compare interrupt Flag）**

寄存器位：TIMx_SR.CCxIF，**捕获/比较中断标志位**

- 输出比较模式（PWM）：当 CNT == CCRx 时硬件自动置1；

- 输入捕获模式：检测有效边沿时硬件自动置1；

- 如果开启CCx中断，该标志置1后进入捕获比较中断；

- **软件写0清零，或者读取SR+清除CCRx自动清零**。

CNT上升走到4、下降走到4，一共两次匹配点。CMS配置决定这两个匹配点是否产生CCxIF。

**3. OCxREF（Output Compare reference signal）**

内部参考波形，**不是引脚输出电平！**

PWM模式内部基准信号；之后再经过 CH Polarity 极性翻转，才得到最终引脚电平。

图中PWM Mode1：

上升段 CNT<4 → OCxREF=高；CNT≥4 → OCxREF=低

下降段 CNT>4 → OCxREF=低；CNT≤4 → OCxREF=高

## **STM32F103 HAL库 TIM-PWM 常用函数接口**

格式统一：**函数原型 + 功能 + 参数 + 返回值**，适配面试/笔记整理

**1. HAL_TIM_PWM_Start**

```C
HAL_StatusTypeDef HAL_TIM_PWM_Start(TIM_HandleTypeDef *htim, uint32_t Channel); 
```

- 功能：启动PWM输出（阻塞方式，不开启中断），使能定时器通道输出PWM波形

- 参数：a. htim：定时器句柄指针 b. Channel：定时器通道 TIM_CHANNEL_1 / TIM_CHANNEL_2 / TIM_CHANNEL_3 / TIM_CHANNEL_4

- 返回值：HAL_StatusTypeDef

- HAL_OK：启动成功

- HAL_ERROR：参数错误、初始化异常

- HAL_BUSY：定时器正在占用

**2. HAL_TIM_PWM_Stop**

```C
HAL_StatusTypeDef HAL_TIM_PWM_Stop(TIM_HandleTypeDef *htim, uint32_t Channel); 
```

- 功能：停止指定通道PWM输出，关闭对应通道PWM信号

- 参数：a. htim：定时器句柄指针b. Channel：定时器通道

- 返回值：HAL_StatusTypeDef

- HAL_OK：停止成功

- HAL_ERROR：参数错误

- HAL_BUSY：外设忙

**3. __HAL_TIM_SET_COMPARE（宏，高频使用）**

```C
__HAL_TIM_SET_COMPARE(TIM_HandleTypeDef *htim, uint32_t Channel, uint32_t CompareValue); 
```

- 功能：设置捕获比较寄存器CCRx的值，**动态修改PWM占空比**

- 参数：a. htim：定时器句柄指针b. Channel：定时器通道c. CompareValue：CCR寄存器数值（0 ~ ARR）

- 返回值：无（预处理宏）

公式：占空比 = CompareValue / (ARR+1)

**4. __HAL_TIM_GET_COMPARE（宏）**

```C
uint32_t __HAL_TIM_GET_COMPARE(TIM_HandleTypeDef *htim, uint32_t Channel);
```

- 功能：读取当前CCRx寄存器的值，获取当前占空比配置

- 参数：a. htim：定时器句柄指针b. Channel：定时器通道

- 返回值：uint32_t 当前CCR寄存器数值

**5. __HAL_TIM_SET_AUTORELOAD（宏）**

```C
__HAL_TIM_SET_AUTORELOAD(TIM_HandleTypeDef *htim, uint32_t Autoreload); 
```

- 功能：动态修改ARR自动重装载寄存器，修改PWM周期/频率

- 参数：a. htim：定时器句柄指针b. Autoreload：ARR寄存器值

- 返回值：无

**6. __HAL_TIM_GET_AUTORELOAD（宏）**

```C
uint32_t __HAL_TIM_GET_AUTORELOAD(TIM_HandleTypeDef *htim);
```

- 功能：读取ARR寄存器数值

- 参数：a. htim：定时器句柄指针

- 返回值：uint32_t ARR寄存器值
