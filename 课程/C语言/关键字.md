# C 语言关键字

> 关键字是 C 语言保留的标识符，由编译器赋予固定语义，不能用作变量、函数、类型或标签名。
> 本笔记按「分类 → 语义 → 存储类组合 → 验证 → 适用边界」组织，重点覆盖嵌入式常用的 const、static、volatile、extern、typedef、register、auto。

## 1. 定义与边界

- 关键字（keyword）由 C 标准规定，词法阶段被识别为固定记号，不参与普通标识符的命名。
- 关键字区分大小写；`const` 是关键字，`Const` 是普通标识符。
- 关键字不能被 `#define` 重定义；用宏名覆盖关键字会让代码行为依赖预处理与编译器实现，禁止使用。
- 预处理器指令（`#include`、`#define`、`#if` 等）以 `#` 开头，不属于关键字。
- 编译器扩展（`__attribute__`、`__packed`、`__interrupt` 等）不是 C 标准关键字，换编译器前要确认支持情况。

## 2. 关键字清单

C89 共 32 个关键字：

| 类别 | 关键字 |
| --- | --- |
| 存储类 | `auto`、`register`、`static`、`extern`、`typedef` |
| 类型限定符 | `const`、`volatile` |
| 基本类型 | `void`、`char`、`short`、`int`、`long`、`float`、`double`、`signed`、`unsigned` |
| 构造类型 | `struct`、`union`、`enum` |
| 控制流 | `if`、`else`、`switch`、`case`、`default`、`for`、`while`、`do`、`break`、`continue`、`goto`、`return` |
| 运算符 | `sizeof` |

C99 增加：`inline`、`restrict`、`_Bool`、`_Complex`、`_Imaginary`。

C11 增加：`_Alignas`、`_Alignof`、`_Atomic`、`_Generic`、`_Noreturn`、`_Static_assert`、`_Thread_local`。

C23 增加不带下划线的 `bool`、`true`、`false`、`static_assert`、`alignas`、`alignof`、`constexpr`、`typeof` 等关键字。

控制流与基本类型在其他笔记展开，以下只讨论与存储、类型修饰和编译行为相关的关键字。

## 3. 存储类说明符

存储类说明符决定对象的存储期、链接属性与作用域。作用域与生命周期的完整规则见 [作用域与存储期](./作用域与存储期.md)。

| 关键字 | 作用域 | 生命周期 | 链接属性 | 典型用途 |
| --- | --- | --- | --- | --- |
| `auto` | 块作用域 | 自动：进入块创建，离开块销毁 | 无 | 块内局部变量的默认存储类，可省略 |
| `register` | 块作用域 | 自动 | 无 | 建议编译器放入寄存器；不能取地址 |
| `static` | 块作用域或文件作用域 | 程序运行全程 | 块内：无；文件内：内部链接 | 函数内保持状态、文件内私有函数或变量 |
| `extern` | 文件作用域或块作用域 | 由定义处决定 | 外部链接 | 声明其他翻译单元中的对象或函数 |
| `typedef` | 声明所在作用域 | 不创建对象 | 无 | 为已有类型建立别名 |

### 3.1 auto

- `auto` 只能用于块作用域对象，表示自动存储期。
- 块内局部变量默认就是 `auto`，日常代码不写；`auto int a = 10;` 与 `int a = 10;` 等价。
- 文件作用域变量不能使用 `auto`。
- C23 起 `auto` 可用于类型推导（`auto x = 1;`）；嵌入式编译器通常不支持该用法，以编译器 `-std` 选项为准。

### 3.2 register

- `register` 向编译器建议把变量放入寄存器，是否接受由编译器决定；被拒绝时按自动变量处理。
- 对 `register` 变量取地址非法：`register int a; &a;` 编译报错。
- 现代优化器能自行决定寄存器分配，`register` 对性能影响有限；嵌入式代码中只在需要禁止取地址或表达意图时使用。

```c
register int count;   /* 建议放入寄存器 */
count = 0;
/* &count;            错误：不能取寄存器变量地址 */
```

### 3.3 static

`static` 的语义随声明位置变化：

| 位置 | 语义 |
| --- | --- |
| 函数内 | 静态存储期：只初始化一次，函数返回后值保留；无链接，其他文件不可见 |
| 文件作用域变量 | 内部链接：只在本翻译单元可见，不会与其他文件的同名全局变量冲突 |
| 文件作用域函数 | 内部链接：只在本文件调用，常用于驱动内部函数 |

```c
static int counter(void)
{
    static int count = 0;   /* 只初始化一次，跨调用保留 */
    return ++count;
}

static void led_on(void)    /* 仅本文件可见 */
{
}
```

- 静态存储期对象未显式初始化时按零初始化；自动变量不保证初值。
- 块内 `static` 变量不在栈上分配，不占用调用栈空间。
- 块内 `static` 变量的初始化表达式必须是常量表达式，初始化在程序启动阶段完成。
- 多线程环境下，块内 `static` 的初始化与修改需要额外同步；`static` 本身不提供线程安全。

### 3.4 extern

- `extern` 声明对象或函数具有外部链接，定义可能在其他翻译单元。
- 声明不分配存储；定义才分配存储。`extern int x;` 是声明，`int x = 0;` 是定义。
- 头文件中声明全局变量用 `extern`，在唯一一个 `.c` 文件中定义，避免重复定义。
- 函数声明默认具有外部链接，`extern void f(void);` 与 `void f(void);` 等价。

```c
/* board.h */
extern int g_tick;              /* 声明 */
void board_init(void);

/* board.c */
int g_tick = 0;                 /* 定义 */
void board_init(void) { }
```

### 3.5 typedef

- `typedef` 为已有类型建立别名，不创建新类型；别名与原类型在类型检查中完全等价。
- 别名遵循作用域规则，可以出现在块内。
- 与 `#define` 的区别：`typedef` 由编译器处理，遵守作用域与类型规则；宏由预处理器做文本替换。

```c
typedef unsigned int size_t;
typedef int array10[10];
typedef int (*pfunc)(int, char);

array10 a;          /* int a[10]; */
pfunc f = NULL;     /* int (*f)(int, char); */
```

结构体别名：

```c
typedef struct node {
    int data;
} Node, *pNode;
/* Node 是 struct node 的别名；pNode 是 struct node * 的别名 */
```

## 4. 类型限定符

### 4.1 const

- `const` 修饰对象，表示程序不能通过该名字修改对象。
- `const` 对象仍占用存储，可以放在只读段（Flash/ROM）；是否放入只读段由链接脚本与编译器决定。
- 在 C 中，`const int` 不是整数常量表达式，不能用于数组长度、`case` 标签或位域宽度；需要编译期常量时使用 `enum`、`#define` 或 C23 的 `constexpr`。

指针与 `const` 的四种组合：

| 声明 | 含义 |
| --- | --- |
| `const int *p;` | 指向 const int 的指针，不能通过 p 修改目标 |
| `int const *p;` | 同上，`const` 在 `*` 左侧修饰目标类型 |
| `int * const p;` | const 指针，p 本身不能改指向，目标可改 |
| `const int * const p;` | 指针与目标都不能改 |

```c
const int a = 10;
const int *p1 = &a;     /* 目标只读，指针可改 */
int * const p2 = &b;    /* 指针只读，目标可改 */
const int * const p3 = &a;
```

- 函数参数用 `const T *` 表达只读入参，既说明意图，也让调用者可以传入 const 对象。
- 强制去掉 `const` 后修改对象属于未定义行为；只读段中的对象写入通常触发硬件异常。

### 4.2 volatile

- `volatile` 告诉编译器该对象的值可能被程序之外的因素改变，每次访问都必须真实读写内存，不能缓存在寄存器中，也不能删除或合并访问。
- `volatile` 不提供原子性、不提供内存屏障、不替代互斥锁；它只约束编译器优化。
- 三类典型场景：内存映射寄存器、中断与主循环共享的变量、多线程共享的标志（配合原子操作或临界区）。

```c
/* 地址以具体芯片手册为准 */
volatile uint32_t * const GPIO_ODR =
    (volatile uint32_t *)0x40020014;
*GPIO_ODR |= (1U << 5);         /* 每次写都落到寄存器 */

volatile uint8_t g_flag;
void EXTI_IRQHandler(void)
{
    g_flag = 1;
}
int main(void)
{
    while (!g_flag) { }         /* 每轮都从内存读取 g_flag */
}
```

延时函数中的用法：

```c
static void delay_loop(void)
{
    volatile uint32_t i = 0x100000;
    while (i--) { }             /* 防止循环被优化掉 */
}
```

- `const volatile` 表示程序不能写、外部可能改，常用于只读硬件状态寄存器。
- 指针声明的位置影响修饰对象：`volatile uint32_t *p` 指向 volatile 对象；`uint32_t * volatile p` 是 volatile 指针。

### 4.3 restrict

- C99 引入，只用于指针，向编译器承诺在指针生命周期内，所指对象只通过该指针及其派生指针访问。
- 违反承诺属于未定义行为；`restrict` 只影响优化，不改变程序语义。
- 标准库中 `memcpy`、`strcpy` 等原型使用 `restrict`，因此源与目标重叠时行为未定义，重叠拷贝要用 `memmove`。

```c
void copy(int n, int *restrict dst, const int *restrict src);
```

## 5. 其他常用关键字

### 5.1 sizeof

- `sizeof` 是运算符，不是函数；结果是 `size_t` 类型，单位字节。
- 操作数可以是类型名（加括号）或表达式；表达式一般不求值，`sizeof(int)`、`sizeof a` 都合法。
- 数组名参与 `sizeof` 得到整个数组大小；数组退化为指针后得到指针大小，这是函数参数中数组长度丢失的原因。
- 变长数组（VLA）的 `sizeof` 在运行时求值。

```c
int a[10];
size_t n = sizeof a;        /* 40（假设 int 为 4 字节） */
size_t m = sizeof(a[0]);    /* 4 */
void f(int a[10]) { sizeof a; }  /* 指针大小，不是 40 */
```

### 5.2 inline

- `inline` 建议编译器内联展开函数，是否展开由编译器决定。
- C99 的 `inline` 只提供内联定义，不产生外部定义；被其他翻译单元调用时需要另一个翻译单元提供外部定义。跨文件使用通常用 `static inline`（头文件中）或在一个 `.c` 中提供外部定义。
- 嵌入式代码常用 `static inline` 写短小的寄存器访问与位操作，减少函数调用开销。

```c
static inline void gpio_set(uint32_t mask)
{
    GPIOA->ODR |= mask;
}
```

### 5.3 其他标准关键字

| 关键字 | 作用 |
| --- | --- |
| `_Bool` | 布尔类型，取值 0 或 1；包含 `<stdbool.h>` 后可用 `bool`、`true`、`false` |
| `_Atomic` | 原子类型限定符与说明符，C11 并发支持 |
| `_Thread_local` | 线程局部存储，C11 |
| `_Static_assert` | 编译期断言，C11；C23 提供关键字 `static_assert` |
| `_Generic` | 泛型选择，C11，常用于宏按类型分派 |
| `_Alignas`、`_Alignof` | 指定与查询对齐，C11 |

## 6. 存储类与限定符组合

| 组合 | 合法性 | 说明 |
| --- | --- | --- |
| `static const int x = 1;` | 合法 | 文件内只读常量 |
| `extern const int x;` | 合法 | 声明其他文件的只读对象 |
| `static inline void f(void);` | 合法 | 头文件中的内部链接内联函数 |
| `const volatile uint32_t *p;` | 合法 | 只读且可能被外部修改的寄存器 |
| `register const int x;` | 合法 | 寄存器变量且只读；不能取地址 |
| `auto static int x;` | 非法 | 两个存储类说明符冲突 |
| `typedef static int T;` | 非法 | `typedef` 不能与其他存储类组合 |
| `static extern int x;` | 非法 | 内部链接与外部链接冲突 |

补充：

- 存储类说明符最多出现一个（C11 的 `_Thread_local` 可与 `static`、`extern` 组合）。
- 类型限定符可以组合，如 `const volatile`；重复写同一限定符在 C99 起允许。
- `static` 修饰函数与变量时含义不同：函数只有内部链接一种语义；变量分块内静态与文件内静态两种情况。

## 7. 常见错误

| 现象 | 原因 | 修正 |
| --- | --- | --- |
| `const int n = 10; int a[n];` 在文件作用域报错 | C 中 const 不是整数常量表达式 | 用 `enum`、`#define` 或块内 VLA |
| `char *p = "abc"; p[0] = 'A';` 崩溃 | 字符串字面量只读 | 用 `const char *p`；需要修改时用字符数组 |
| 中断改变量、主循环不退出 | 变量未加 `volatile`，被优化进寄存器 | 对共享变量加 `volatile` |
| `volatile` 保护多线程计数仍出错 | `volatile` 不保证原子性 | 原子操作或互斥锁 |
| 头文件定义变量导致重复定义 | 头文件写了定义而非 `extern` 声明 | 头文件用 `extern`，一个 `.c` 中定义 |
| `register int a; &a;` 编译错误 | 寄存器变量无内存地址 | 去掉 `register` 或改为普通变量 |
| 函数参数 `sizeof` 得到指针大小 | 数组形参退化为指针 | 额外传长度或使用结构体封装 |
| `inline` 函数链接错误 | 只提供内联定义，缺少外部定义 | 用 `static inline` 或补外部定义 |

## 8. 验证方法

关键字行为由编译器与优化级别决定，可用以下方式验证：

```bash
# 保存中间汇编，观察 const/volatile/static 的生成结果
gcc -std=c11 -O2 -S keywords.c -o keywords.s

# 查看符号表，确认 static 符号为 local、extern 符号为 global
gcc -std=c11 -c keywords.c -o keywords.o
nm keywords.o

# 对比 volatile 变量在 -O2 下的读写次数
objdump -d keywords.o
```

验证要点：

1. `static` 文件作用域函数在 `nm` 输出中为小写 `t`（local），非 static 函数为大写 `T`（global）。
2. `volatile` 变量在优化后仍保留每次读写的指令；去掉 `volatile` 后循环可能被删除。
3. `const` 对象在只读段（`.rodata`）中，写入会触发异常；用 `objdump -h` 查看段布局。
4. `sizeof` 的结果用 `printf("%zu\n", sizeof(...))` 验证，避免用 `%d` 打印 `size_t`。

## 9. 适用边界

- 标准版本：C89、C99、C11、C17、C23 的关键字集合不同；嵌入式工具链常见 C99/C11，使用新关键字前确认编译器 `-std` 支持。
- 编译器扩展：`__attribute__`、`__packed`、`__interrupt` 等不属于标准 C；跨编译器移植时用宏封装并注明依赖。
- C++ 差异：C++ 增加 `class`、`namespace`、`template` 等关键字，`const` 的常量表达式语义与 C 不同；C 与 C++ 混合编译需要 `extern "C"`。
- `volatile` 与并发：C11 之前的标准没有内存模型，`volatile` 不能替代原子操作；多核与中断场景要结合硬件手册与编译器内存序说明。
