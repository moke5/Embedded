# embedded-knowledge-sync

## 1. 目标

将当前对话中具有长期复用价值的技术知识写入本 Skill 所在仓库的根目录（本仓库当前为 `d:\git\embedded`；跨机器使用时按 `SKILL.md` 的上两级目录定位），同时避免重复造笔记、错误归档和修改代码。

知识沉淀结果只有三类：

```text
结果 = 已存在
    ∨ 已补充
    ∨ 已新建
```

## 2. 硬边界

- 工作根目录限定为本 Skill 所在仓库根目录，即 `.skills/embedded-knowledge-sync/SKILL.md` 的上两级目录。
- 只修改 Markdown、YAML、PlantUML/Mermaid 源码和笔记所需图片说明；代码文件只读，除非用户当次明确授权修改代码。
- 不写入 `D:/git/AI`，不自动归档到其他仓库。
- 不写入私钥、token、服务器公网 IP、账号明细、本机敏感配置；敏感内容引用 `self/` 路径但不展开。
- 不执行 git commit、push、删除、移动、批量重命名；用户明确要求时另行确认。
- 内容证据不足、目标归档目录存在多个合理候选，或新建笔记会改变知识结构时，先询问用户。

## 3. 启动流程

1. 读取仓库根目录 `AGENTS.md`。
2. 从当前对话提取待沉淀知识点：
   - 概念定义、术语全称、协议机制；
   - 命令、参数、配置、环境依赖；
   - 错误现象、根因、排查条件、修复与回滚；
   - 对比关系、流程、状态机、架构图；
   - 可复用的操作流程和验证方法。
3. 排除一次性内容：临时结果、未验证猜测、闲聊、密钥、密码、token、完整个人环境明细。
4. 为每个知识点确定中文主题名、英文技术专名、命令名或错误字符串，作为检索词。

## 4. 检索顺序

1. 读取可能相关的顶层或主题 `MOC.md`，确定权威入口。
2. 用中文主题名、英文术语、命令名、配置项和错误信息全文检索 `**/*.md`。
3. 打开候选笔记正文，不只依据文件名或检索片段判断。
4. 检查候选笔记的 frontmatter、标题层级、双链和 `related` 字段。
5. 若知识点跨越多个主题，先确定主笔记；其他主题只建立链接，不重复正文。

初始路由参考，实际归档以 MOC 和检索结果为准：

| 知识点类型 | 初始候选位置 |
| --- | --- |
| Bash 语法、Shell 展开、脚本结构 | `杂记/工具/bash.md` |
| 终端编辑快捷键 | `杂记/工具/bash快捷键.md` |
| Linux 通用命令、文件、网络、路径 | `杂记/Linux/基础命令速查.md` |
| SSH、OpenSSH、终端连接环境 | `杂记/环境/ssh.md` |
| 编辑器、Remote-SSH | `杂记/工具/vscode.md` |
| 服务器部署、登录、安全组 | `杂记/服务器/` |
| STM32、ESP32、课程章节知识 | `课程/` 对应主题 |
| 工具软件使用 | `杂记/工具/` |
| 环境安装与系统问题 | `杂记/环境/` |

## 5. 判定规则

### 5.1 已存在

满足以下条件时不修改文件：

```text
已存在 ⇔ 同一概念边界
       ∧ 同一适用条件
       ∧ 关键命令/参数/机制已覆盖
       ∧ 现有表述符合 AGENTS.md 第 7 节
```

回报文件路径、标题和匹配位置。若只存在格式差异，不重复写入。

### 5.2 已补充

存在相关笔记且缺少本次知识点时，在最权威的既有笔记中补充：

- 新命令、参数或边界条件；
- 概念定义、公式、图、错误现象、验证方法；
- 到其他笔记的双链；
- 必要的来源链接。

补充后更新：

- frontmatter 的 `updated`；
- `output` 或 `related`（如内容变化需要）；
- 相关 MOC 的条目说明（仅当索引描述无法覆盖新内容时）。

### 5.3 已新建

同时满足以下条件才新建：

```text
新建 ⇔ 无现成权威笔记
     ∧ 知识点无法作为小节并入既有笔记
     ∧ 内容具有长期复用价值
     ∧ 归档目录可由 MOC 确定
```

新建流程：

1. 读取 `模板/模板说明.md`，选择模板。
2. 按模板创建 Markdown 文件，命名遵守 AGENTS.md 第 3 节。
3. 填齐 frontmatter。
4. 正文遵循 AGENTS.md 第 7 节：定义、符号、推导、图、操作、验证、结论。
5. 遇到仓库已有知识点时使用 `[[笔记名]]`，并同步 `related`。
6. 将新笔记加入对应主题的 `MOC.md`。

## 6. 写作约束

- 首次出现的概念给出定义、持有方、作用域、输入、输出和边界。
- 命令必须给出适用环境、前置条件和验证方法；危险操作给出回滚路径。
- 条件关系优先用公式、谓词、集合或表格；符号必须先定义。
- 多方协议、架构、状态迁移、排查分支必须配图；图默认使用 Mermaid 源码并标注为 `mermaid`，确保 Obsidian 原生渲染；用户明确要求 PlantUML 或确认已启用 PlantUML 插件时除外。
- 每张图包含编号、图题、明确箭头语义和图后结论。
- 外部事实、兼容性结论、版本依赖保留来源链接。
- 同一事实只在一个权威位置展开，其他位置使用双链。
- 不复制用户私密文件内容，不输出私钥正文。

## 7. 验证与交付

修改完成后执行：

1. 回读所有修改段落和新文件。
2. 检查 frontmatter、MOC 链接、相对路径、wikilink 和图代码。
3. 用检索确认新增关键词可被找到。
4. 检查是否存在重复定义、敏感信息和代码文件改动。
5. 向用户交付文件路径，并按以下格式回报：

```text
判定：已存在 / 已补充 / 已新建
检索：使用的关键词与候选笔记
修改：
- 文件路径：新增或修改的标题
- MOC：是否更新及原因
验证：回读、链接、关键词、敏感信息检查结果
遗留：证据不足或需用户确认的问题
```

## 8. 触发示例

- “使用知识沉淀 skill，把刚才的 realpath 命令加进仓库。”
- “使用这个 skill，整理本次 SSH 报错。”
- “把这次对话沉淀到 embedded 笔记。”
- “检查仓库里有没有这个 Linux 命令，没有就补上。”
