# 仓库信息架构

> 定义 AGENTS.md、CLAUDE.md、README.md 与 规范/ 的读者、职责和迁移顺序。本文件是方案与执行记录；入口文件已于 2026-11-03 按本方案改造。

## 1. 结论

| 文件 | 定位 | 读者 |
| --- | --- | --- |
| `AGENTS.md` | 仓库级 Agent 契约：定位、硬约束、目录地图、命令、门禁、索引 | AI Agent |
| `CLAUDE.md` | Claude Code 的薄适配，指向 AGENTS.md | Claude Code |
| `README.md` | 仓库门面：定位、目录导航、快速开始、规范索引 | 人 |
| `规范/` | 仓库级详细规则：写作、校验与提交、Agent 协作 | 人、Agent |
| `MOC.md` | 知识检索入口 | 人、Agent |

三条原则：

1. 单一事实源：同一规则只在一个文件定义，其他位置给链接。
2. 渐进披露：入口保留最小可执行上下文，细节按需打开。
3. 链接可解析：入口文件用相对 Markdown 链接；Obsidian 双链留在笔记和 MOC。

### 1.1 作用域

| 层级 | 位置 | 生效范围 | 内容 |
| --- | --- | --- | --- |
| 全局 | `~/.claude/CLAUDE.md`、`~/.config/opencode/AGENTS.md` | 所有项目 | 个人偏好、跨项目约束 |
| 仓库 | `AGENTS.md` | 本仓库 | 目录、命令、硬约束、索引 |
| 工具 | `CLAUDE.md`、`.cursor/rules/`、`.skills/` | 本仓库与特定工具 | 薄适配与工具能力 |
| 笔记 | frontmatter、正文 | 单篇 | 类型、标签、内容 |

仓库根的 `AGENTS.md` 只在本仓库生效；跨项目的个人规则放在用户级配置。

### 1.2 读者与内容边界

| 读者 | 入口 | 需要回答的问题 | 不承担 |
| --- | --- | --- | --- |
| 初次访问者 | `README.md` | 这是什么、目录怎么走、从哪里开始 | Agent 细则、长推导 |
| AI Agent | `AGENTS.md` | 能做什么、不能做什么、怎么校验、细则在哪 | 教程、历史记录 |
| Claude Code | `CLAUDE.md` | 去哪里读统一规则 | 重复规则 |
| Cursor | `.cursor/rules/` | 工具特有约束 | 重复规则 |
| 知识检索 | `MOC.md` | 某个主题的入口 | 仓库规范 |
| 维护者 | `规范/` | 规则原文、迁移任务、验收 | 学习笔记 |

## 3. 目标结构

```text
.
├── AGENTS.md          # Agent 契约：定位、硬约束、目录地图、命令、门禁、索引
├── CLAUDE.md          # 薄适配：指向 AGENTS.md
├── README.md          # 人类门面：定位、目录、快速开始、规范索引
├── 规范/
│   ├── MOC.md                # 规范目录索引
│   ├── 仓库信息架构.md        # 本文件
│   ├── 写作与笔记规范.md      # 命名、frontmatter、文风、图、新建流程
│   ├── 校验与提交规范.md      # lint、钩子、分支、提交、推送
│   └── Agent协作规范.md       # 工具适配、权限、跨库、本机能力入口
├── 模板/模板说明.md
├── 本机/规范.md
└── 项目/仓库规范与工具链建设.md
```

`规范/` 是内容目录，配 `MOC.md`；`模板/`、`本机/`、`项目/` 保持原位，负责各自领域。

## 4. AGENTS.md 目标大纲

目标：60–80 行，8 节，入口只保留决策所需信息。

| 节 | 内容 | 行数预算 |
| --- | --- | --- |
| 1 作用域与优先级 | 全局、仓库、工具、笔记四级；冲突时安全 > 用户指令 > AGENTS > 默认 | 6–8 |
| 2 硬约束 | 隐私、跨库、权限、破坏性操作、提交边界 | 12–15 |
| 3 目录地图 | 8 个顶层目录，每行一句加 MOC 链接 | 10–12 |
| 4 常用命令 | lint、本机能力、git 检查 | 8–10 |
| 5 写入门禁 | frontmatter、MOC、链接、命名底线 | 8–10 |
| 6 规范索引 | 按问题列链接 | 8–10 |
| 7 工具适配 | CLAUDE、Cursor、Skills 的薄适配 | 5–8 |
| 8 冲突与例外 | 冲突处理与征询条件 | 5 |

硬约束保留项：

- 敏感信息写入 `self/`，不入库；不写真实 IP、token、凭据。
- 安装、下载、修改系统配置、写凭据前征得用户同意。
- 未经要求不提交、不推送、不做破坏性操作。
- 写入 `D:/git/AI` 前读目标库 `CLAUDE.md`，不夹带本仓库文件。
- 大规模重命名前提醒关闭 Obsidian、Typora。
- 全盘检索、打开本机软件前先读 [本机/能力清单.json](../本机/能力清单.json)。

写入门禁保留项：

- 新笔记必填 `type`、`tags`、`status`、`created`、`updated`。
- 新笔记接入所属 MOC；重命名同步更新 MOC 与双链。
- 入口文件用相对 Markdown 链接，笔记与 MOC 用双链。
- 校验命令：`python script/notes_lint.py --strict`。

## 8. 风险与回滚

| 风险 | 触发条件 | 缓解 |
| --- | --- | --- |
| Agent 不跟随链接 | 入口只给链接，缺少关键约束 | 硬约束与命令留在 AGENTS 正文 |
| 规则漂移 | 同一规则在两处维护 | 单一事实源矩阵加评审检查 |
| 双链失效 | 入口使用 `[[...]]` | 入口统一相对 Markdown 链接 |
| 规范目录无索引 | 新增 `规范/` 未建 MOC | T1 先建 `规范/MOC.md` |
| 中间态不可用 | 先删 AGENTS 再写规范 | 先建规范，再重写入口 |

回滚方式：每个任务单独提交；出现问题时 `git revert` 对应提交。改动前确认工作区干净。
