# 知识分层方案

> 一句话结论：以“能力层级”为第一分类轴，以“技术领域”和“笔记形态”为辅助轴；`课程` 只作为来源写入 `input`，不再作为目录或 `type`。

## 1. 原则

1. **层级优先**：先判断一条知识属于哪一层能力，再判断它属于哪个平台或领域。
2. **目录存位置，元数据存语义**：目录用于存放与浏览；精确层级、领域、前置知识以 frontmatter 为准。
3. **单一来源**：`layer`、`domain`、`prereq` 只写一次，索引由脚本生成，不手工复制。
4. **平台可跨层**：同一平台（STM32、ESP32）可以出现在多个层级；共享资源跟随主层级，避免重复。
5. **渐进迁移**：先补元数据与索引，再移动目录；每一步可回滚。

## 2. 层级模型

层级用“能做什么”定义，便于判断归属。

| 层 | 名称 | 能力边界 | 典型内容 |
| --- | --- | --- | --- |
| L0 | 物理与电路 | 能读电路图、选元件、画 PCB、焊接与调试硬件 | 电路分析、模拟/数字电路、PCB、焊接、电源、信号完整性 |
| L1 | 芯片与外设 | 能配置时钟、GPIO、中断、定时器、ADC、DMA 与总线 | MCU/SoC 架构、启动流程、GPIO、UART、I2C、SPI、ADC、RTC |
| L2 | 驱动与固件 | 能写寄存器/HAL 驱动并做分层封装与状态管理 | 驱动分层、设备模型、中断处理、状态机、传感器驱动、阶段实验 |
| L3 | 实时与内核 | 能用 RTOS 调度/同步，理解 Linux 进程、线程、IPC、VFS | FreeRTOS、任务与同步、进程/线程、IPC、文件系统、内核子系统 |
| L4 | 系统编程与构建 | 能用 C/数据结构/编译链接/构建工具组织可维护代码 | C 语言、数据结构、内存、编译链接、静态/动态库、make/cmake、调试 |
| L5 | 网络与协议 | 能实现 socket 通信并接入常见应用协议与无线链路 | TCP/UDP、IO 模型、HTTP/MQTT/CoAP、WiFi/BLE/ZigBee、云接入 |
| L6 | 应用与交互 | 能完成 GUI、上位机、小程序与云端交互 | LVGL、GUI、微信小程序、上位机、云平台应用 |
| L7 | 集成与产品 | 能软硬协同、测试、部署并交付完整项目 | 项目架构、软硬协同、测试、部署、运维、安全 |
| X | 工具与方法 | 能用工具链、服务器、AI 与规范提升效率 | git、vim、VS Code、终端、服务器、AI 协作、学习方法、仓库规范 |

| 字段 | 取值 | 说明 |
| --- | --- | --- |
| `type` | 概念 / 实验 / 踩坑 / 对比 / 练习 / 自测 / 复习 / 项目 / 速查 / 读书 / 工具 / MOC | 笔记形态；`课程` 已弃用 |
| `layer` | L0–L7 / X | 精确层级 |
| `domain` | hardware / mcu / rtos / linux / network / gui / tool / project | 技术领域 |
| `prereq` | `[[笔记]]` 列表 | 前置知识，通常指向更低层或同层先修 |
| `related` | `[[笔记]]` 列表 | 横向关联 |

来源写入 `input`，例如 `input: 2026 嵌入式培训第 3 期`。不再用 `tags: [课程]` 或 `type: 课程` 表示来源。

## 5. 跨层平台规则

1. 平台拥有一个**主层级**，平台目录放在主层级下。STM32 的主层级为 L1。
2. 明确属于更高层的笔记，放入对应层级目录；同一平台的共享图片留在主层级。
3. 次级层级的笔记只复制自己引用的图片，避免整目录复制。
4. 目录与 `layer` 冲突时，以 `layer` 为准；生成索引会按 `layer` 归类。
5. 平台入口页列出跨层学习路径，解决“同一平台被拆开”后的浏览问题。

## 6. 索引生成

`script/build_index.py` 读取 frontmatter，生成：

- `知识地图/层级索引.md`：按 L0–L7、X 分组。
- `知识地图/领域索引.md`：按 domain 分组。
- `知识地图/依赖关系.md`：由 `prereq` 生成 Mermaid 图。

生成物只做汇总，人工 `MOC.md` 仍是浏览入口。`--check` 模式用于校验缺字段与非法取值。

## 7. 迁移步骤

1. **备份**：完整复制工作区，校验文件数与哈希。
2. **定标准**：写入本文件，更新 `模板说明`、`写作与笔记规范` 与模板。
3. **补元数据**：按平台批量补 `layer`/`domain`/`prereq`，替换 `type: 课程`。
4. **建索引**：运行 `build_index.py`，检查未标注项与依赖方向。
5. **移动目录**：关闭 Obsidian、Typora 后移动文件；更新 MOC 与相对链接。
6. **验收**：`notes_lint.py --strict` 为 0，索引无断链，旧目录无残留。
