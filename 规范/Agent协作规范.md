# Agent 协作规范

> 本文件是 Agent 工具适配、权限边界、本机能力、Skill 与跨库协作的唯一来源；`AGENTS.md` 只保留硬约束摘要。

## 1. 工具适配

| 工具 | 文件 | 职责 |
| --- | --- | --- |
| 通用 Agent | `AGENTS.md` | 仓库级契约与索引 |
| Claude Code | `CLAUDE.md` | 指向 AGENTS.md 与规范索引 |
| Cursor | `.cursor/rules/本机能力.mdc` | 本机能力调用 |
| 仓库 Skill | `.skills/embedded-knowledge-sync/SKILL.md` | 知识沉淀流程 |

工具文件只做薄适配，不重复 `AGENTS.md` 与 `规范/` 的规则。规则变更先改主文件或对应规范，再同步工具文件。

## 2. 权限与确认

| 操作 | 规则 |
| --- | --- |
| 安装、下载、升级软件 | 先查官方文档或 GitHub，报告仓库、许可证、安装方式与风险，征得用户同意 |
| 修改系统配置、环境变量 | 征得用户同意 |
| 写入凭据、token、私钥 | 征得用户同意；凭据只放 `self/` |
| 删除、移动、批量重命名 | 征得用户同意；大规模重命名前提醒关闭 Obsidian、Typora |
| 提交、推送、强制推送 | 未经用户要求不执行；推送前确认 |
| 修改代码文件 | 默认只读；用户当次明确授权后才修改 |

## 3. 本机能力优先

涉及全盘文件名检索、用本机应用打开文件、操作本机软件或系统集成的任务，按以下顺序；仓库内的内容检索（Grep/Glob）和文件读写不在此列：

1. **发现**：先读 [本机/能力清单.json](../本机/能力清单.json)，或运行 `.\script\local.ps1 list`（可按 tag 过滤）。
2. **命中**：调用清单里的适配器；一次性临时脚本需说明用途并在用完后清理，长期能力按 [本机/规范.md](../本机/规范.md) 登记。
3. **未命中**：查官方文档或 GitHub，报告仓库、许可证、安装方式与风险，不直接下载。
4. **确认**：安装、下载、修改系统配置、写凭据前征得用户同意。
5. **落账**：新增能力须同时更新清单、适配器、`本机/能力/<名>.md` 与 `本机/MOC.md`。

## 4. 仓库本地 Skill

- [embedded-knowledge-sync](../.skills/embedded-knowledge-sync/SKILL.md)：当用户说“使用知识沉淀 skill”“使用这个 skill 整理本次对话”，或要求把当前对话中的技术知识点回写到本仓库时，先读取该 Skill，再按其检索、判定、补充或新建 Markdown，并回报修改路径。

## 5. 跨库协作：D:/git/AI

本机另一个仓库 `D:/git/AI` 是 AI 知识库，与本仓库分工不同：

| 仓库 | 定位 | 维护方式 |
| --- | --- | --- |
| `D:/git/AI` | AI 会话记忆：个人长期偏好、会话总结、结构化 AI/Agent 知识 | 各类 AI 会话按该库 `CLAUDE.md` 自行归档 |
| 本仓库（`D:/git/embedded`） | 个人技术学习笔记：课程、项目、杂记 | 人工整理为主，AI 辅助 |

`AI/` 是本仓库的 AI/Agent 技术学习笔记，属于本仓库内容；`D:/git/AI` 是独立会话记忆库，两者不混用。

跨库约束：

- 向 `D:/git/AI` 写入前完整读取该库 `CLAUDE.md`，按其目录、模板与命名规则执行；两库规则冲突时以目标库规则为准。
- 只归档本次会话产物（会话总结、知识条目、个人记忆），不将本仓库笔记整批复制过去，也不夹带本仓库文件。
- 本仓库内容不自动跨库归档；用户要求沉淀到 AI 库时，先说明将写入的路径与内容范围。
- 敏感信息规则仍然适用；从 AI 库引用内容到本仓库时只注明来源，不整段复制。

## 6. 冲突与例外

- 冲突时按“安全与隐私 > 用户明确指令 > AGENTS.md > 默认文风”处理；仍冲突时先询问用户。
- 用户明确要求的例外，在对应规范或项目记录中登记原因与范围。
- 发现规则过时或互相矛盾时，报告位置和影响，不自行扩大解释。
