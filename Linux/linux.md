内核对象

```
内核为了管理某种资源而创建的数据结构。
生命周期由内核管理。
用户程序不能直接访问。
只能通过系统调用间接操作。
```



### 目录

`/proc` 是 Linux 中一个非常特殊的“伪文件系统目录”，不是磁盘上的真实目录，而是 **内核运行时信息的接口层（virtual filesystem）**。



##### 1. 本质：内核信息的“映射窗口”

`/proc` = **procfs（process filesystem）**

它不存储实际文件数据，而是：

- 把 **内核数据结构**
- 动态“映射”为文件形式
- 供用户态程序读取/修改

可以把它理解为：

> 用户态访问内核状态的一种“文件化接口”



##### 2. 内容来源：运行时动态生成

`/proc` 里的文件 **不是磁盘文件**，而是：

- 读取时由内核实时生成内容
- 写入时直接影响内核行为

例如：

```
cat /proc/cpuinfo
```

👉 CPU 信息不是存储在文件里，而是内核直接输出当前 CPU 状态。



##### 3. 常见结构（核心分类）

###### （1）进程信息 `/proc/[pid]/`

每个进程都有一个目录：

```
/proc/1234/
```

里面包含：

- `cmdline` → 启动命令
- `status` → 进程状态
- `fd/` → 打开的文件描述符
- `maps` → 内存映射

👉 本质：内核进程控制块（PCB）的可视化



###### （2）系统级信息

| 文件            | 作用         |
| --------------- | ------------ |
| `/proc/cpuinfo` | CPU 信息     |
| `/proc/meminfo` | 内存使用情况 |
| `/proc/uptime`  | 系统运行时间 |
| `/proc/version` | 内核版本     |



###### （3）内核参数（可调）

```
/proc/sys/
```

例如：

```
/proc/sys/net/ipv4/ip_forward
```

可以：

```
echo 1 > /proc/sys/net/ipv4/ip_forward
```

👉 直接修改内核行为（网络转发开启）



##### 4. 和普通文件系统的区别（关键点）

| 项目         | /proc          | ext4 等磁盘文件系统 |
| ------------ | -------------- | ------------------- |
| 是否真实存储 | ❌ 否           | ✅ 是                |
| 是否占磁盘   | ❌ 不占         | ✅ 占                |
| 内容来源     | 内核动态生成   | 磁盘                |
| 生命周期     | 随系统运行变化 | 持久化              |



##### 5. 为什么设计 `/proc`？

核心目的：**让用户态可以“像读文件一样访问内核”**

否则你需要：

- 写内核模块
- 用 ioctl / syscall
- 或调试接口

而 `/proc` 提供：

👉 统一、简单、可脚本化访问方式
